### 三、先分清训练中的六种东西

| 名称 | 谁提供它 | 在训练中起什么作用 | 一个例子 |
| --- | --- | --- | --- |
| 输入数据 | 数据集 | 交给模型处理 | 一张图片、一个视频片段 |
| 标注或目标 | 人工标注或任务定义 | 告诉训练程序期望的答案 | 物体框、类别、“拿着”关系 |
| 参数 | 模型初始化，随后被训练调整 | 控制模型如何计算 | 线性层权重与偏置 |
| 预测 | 模型按当前参数算出 | 给出当前答案或得分 | 预测框、类别得分 |
| 损失 | 比较预测与目标 | 衡量当前预测与监督的差距 | 平方误差、交叉熵 |
| 梯度 | 对损失求导 | 描述损失对各参数的局部变化率 | `model.weight.grad` |

输入、标注和参数要分别看。模型输出类别，并不会自动产生正确的训练标注；求导得到梯度，也不会自动更新参数。

### 四、贯穿全套的例子

考虑一段视频：一个人先看杯子，然后拿起杯子，最后喝水。

```text
视频帧的像素
    ↓
检测物体：人、杯子；估计它们的位置
    ↓
为物体和物体对计算特征
    ↓
结合同帧和跨帧的信息
    ↓
输出关系得分
    ↓
形成三元组：人—看着—杯子、人—拿着—杯子等
```

训练时，还要把预测与已知标注比较，计算损失，再求导和更新模型参数。ImparTail 关注关系监督的分布：常见关系出现很多次，少见关系出现很少；它通过掩码策略改变哪些关系损失在本次训练中参与学习。

这张流程图帮助理解常见的物体中心视频场景图方法；具体模型会有不同的检测、特征处理和关系模块。

### 五、怎样读公式

看到公式时，按四步读：

1. **找输入与输出。** 例如 `Y=XW+b`，输出是 Y。
2. **标形状。** 例如 X 为 `[样本数, 输入特征数]`。
3. **判断操作。** 这里有矩阵乘法和偏置相加。
4. **代入小数字。** 先用一两条样本算一次，再理解大的张量。

看到导数时额外问一句：“对谁求导？”`dL/dw` 表示损失 L 对参数 w 的导数，不是对损失再平方，也不是对上一次保存的梯度求导。

### 六、怎样读代码

先给变量写上中文解释，然后记录形状，再找出三类语句：

```python
prediction = model(inputs)     # 用当前参数计算预测
loss = criterion(prediction, targets)  # 根据预测和标注计算损失
loss.backward()               # 计算梯度
optimizer.step()              # 使用梯度更新参数
```

注意当前变量代表的是更新前还是更新后的结果。参数更新后，旧预测不会自行重算。

遇到张量维度操作，用“旧顺序→新顺序”写出来，例如 `[高,宽,通道]→[通道,高,宽]`，比直接背 `permute(2,0,1)` 更容易迁移到新任务。

### 1．图片为什么可以写成数字

#### 1.1 一个像素是什么

把图片放大，会看到许多小格子。每个格子是一个像素。电脑处理的是这些位置上的数字，显示设备再把数字变成你看到的颜色。

**灰度图片**通常每个像素只有一个强度值。对于常见的 8 位表示，0 表示黑，255 表示白，中间数字表示灰色。这里的 8 位意味着共有 \(2^8=256\) 种整数取值，即 0～255。

例如一张两行三列的灰度图片：

```text
  0  128  255
255  128    0
```

在代码中，它就是一个形状为 `[2, 3]` 的矩阵。

#### 1.2 彩色图片为什么有三个通道

常见 RGB 图片使用三个通道：

| 通道 | 中文 | 通道编号 |
| --- | --- | --- |
| R | 红色分量 | 0 |
| G | 绿色分量 | 1 |
| B | 蓝色分量 | 2 |

一个像素就是三个数：

```text
红色：[255,   0,   0]
绿色：[  0, 255,   0]
蓝色：[  0,   0, 255]
白色：[255, 255, 255]
黑色：[  0,   0,   0]
灰色：[128, 128, 128]
```

“红色通道”不是“图片里所有红色物体”，而是每个位置上的红色分量。一件白色物体的红色分量也可能很高，因为白色同时包含三个通道的高值。

并非所有图片都天然是 RGB、8 位或三个通道。例如灰度图片可以只有一个通道，带透明度的图片可以有第四个通道，其他格式也可以用更大的数值范围。我们现在先学习最常见的 RGB 情况。

#### 1.3 手工创建一张两行两列图片

我们让图片的四个位置分别是：

```text
红色  绿色
蓝色  白色
```

对应代码：

```python
import torch

image_hwc = torch.tensor([
    [[255, 0, 0], [0, 255, 0]],       # 第一行：红色、绿色
    [[0, 0, 255], [255, 255, 255]]    # 第二行：蓝色、白色
], dtype=torch.uint8)

print(image_hwc.shape)  # torch.Size([2, 2, 3])
print(image_hwc.dtype)  # torch.uint8
```

`torch.uint8` 表示无符号 8 位整数，适合保存这里的 0～255 数值。张量的形状是 `[高度, 宽度, 通道数]`，简称 HWC。

### 2．看懂图片张量的形状和索引

#### 2.1 为什么是 `[2, 2, 3]`

把三个维度分开看：

```text
第 0 维：高度 H = 2，两行
第 1 维：宽度 W = 2，两列
第 2 维：通道 C = 3，每个位置有 RGB 三个数字
```

整张图片共有 \(2\times2\times3=12\) 个数字。

注意“二维图片”和“三维张量”可以同时成立：图片的空间有高、宽两个方向，但保存颜色时还增加了通道维度。

#### 2.2 取出一个像素

HWC 排列的索引顺序是：

```python
image_hwc[row, column, channel]
```

例子：

```python
print(image_hwc[0, 1])     # 第一行第二列：[0, 255, 0]，绿色
print(image_hwc[1, 0])     # 第二行第一列：[0, 0, 255]，蓝色
print(image_hwc[0, 1, 1])  # 绿色像素的绿色分量：255
```

不写第三个索引时，会保留该位置的全部三个通道。

#### 2.3 取出一个颜色通道

```python
red_channel = image_hwc[:, :, 0]  # 所有行、所有列、红色通道
print(red_channel)
```

结果：

```text
tensor([[255,   0],
        [  0, 255]], dtype=torch.uint8)
```

红色像素和白色像素的红色分量都是 255。

**小检查：**`image_hwc[:, :, 2]` 应该输出什么？先把蓝色分量写成两行，再运行核对。

```text
[[0,   0],
 [255, 255]]
```

第一行的红色和绿色像素没有蓝色分量；第二行的蓝色和白色像素有蓝色分量。

### 3．HWC、CHW 和 NCHW：顺序不同，含义就不同

#### 3.1 为什么要换顺序

常见图像读取流程会给出 `[高度, 宽度, 通道]`。PyTorch 的二维卷积常用 `[批次, 通道, 高度, 宽度]` 作为输入，单张未加批次的图片对应 CHW。[二维卷积输入约定](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Conv2d.html)

| 简写 | 维度顺序 | 一张高 32、宽 64 的 RGB 图片 |
| --- | --- | --- |
| HWC | 高度、宽度、通道 | `[32, 64, 3]` |
| CHW | 通道、高度、宽度 | `[3, 32, 64]` |
| NCHW | 批次、通道、高度、宽度 | 单张：`[1, 3, 32, 64]` |

其中 N 是一起处理的图片数。如果一次处理 8 张同样大小的 RGB 图片，NCHW 是 `[8, 3, 32, 64]`。

不要看到三个维度就猜它一定是 CHW。形状的含义来自数据约定和代码，数字本身不会告诉你哪一维是通道。

#### 3.2 用 `permute` 调整维度顺序

```python
image_chw = image_hwc.permute(2, 0, 1)
print(image_chw.shape)  # torch.Size([3, 2, 2])
```

`permute` 的作用是重新排列维度。[官方说明](https://docs.pytorch.org/docs/2.14/generated/torch.permute.html)

这里 `2, 0, 1` 是**原来的维度编号**：

```text
原顺序：第 0 维是高度，第 1 维是宽度，第 2 维是通道
新顺序：先放原第 2 维，再放原第 0 维，最后放原第 1 维

[H, W, C] → [C, H, W]
```

结果可以看成三张两行两列的矩阵：

```text
红色通道：      绿色通道：      蓝色通道：
255    0          0  255          0    0
  0  255          0  255        255  255
```

这不是给图片旋转 90 度，也不是交换红色和蓝色。颜色和位置的对应关系仍然保留，只是读取时的维度顺序改变了。

同一个绿色像素的读取方式变成：

```python
image_hwc[0, 1, :]  # 行、列、全部通道
image_chw[:, 0, 1]  # 全部通道、行、列
```

两者都是 `[0, 255, 0]`。

**不要用 `reshape(3, 2, 2)` 代替这次 `permute`。**`reshape` 重新组织形状，不表达“把原第 2 维移到前面”的关系，可能打乱像素与通道的对应。

#### 3.3 用 `unsqueeze` 加上批次维度

```python
image_nchw = image_chw.unsqueeze(0)
print(image_nchw.shape)  # torch.Size([1, 3, 2, 2])
```

`unsqueeze(0)` 在第 0 个位置插入一个长度为 1 的维度。[官方说明](https://docs.pytorch.org/docs/2.14/generated/torch.unsqueeze.html)

```text
[3, 2, 2] → [1, 3, 2, 2]
              ↑
           有一张图片
```

它没有把一张图片变成两张图片，也没有增加新像素。

如果已有两张同形状的图片，可以用：

```python
batch = torch.stack([image_chw, image_chw], dim=0)
print(batch.shape)  # [2, 3, 2, 2]
```

这里为了示范，把同一张图片重复两次。真实训练应放入对应的不同样本。

### 4．为什么转成浮点数，为什么除以 255

#### 4.1 数据类型和数值范围是两回事

```python
image_float = image_chw.float()
```

这一步把整数张量变成浮点张量：

```text
原来：255，类型是 uint8
之后：255.0，类型是 float32
```

**`.float()` 本身不会把 255 变成 1。**它改变数据类型，不自动缩放数值。

模型的权重和许多运算使用浮点数，所以常见预处理会把图片也转成浮点数。

#### 4.2 将 0～255 缩放为 0～1

```python
image_01 = image_chw.float() / 255.0
```

对每个像素分量做：

\[
新值=原值/255
\]

| 原值 | 缩放后 |
| --- | --- |
| 0 | 0 |
| 128 | 约 0.502 |
| 255 | 1 |

我们在这份教材中把这种固定范围缩放称为**归一化**。实际资料里“归一化”一词可能指不同操作，要看它的公式。[TorchVision 图像数据类型与范围约定](https://docs.pytorch.org/vision/stable/transforms.html)

这是一种常见输入处理，但不能据此认为“任何模型都只接受 0～1”。真实项目必须使用该模型要求的预处理。

#### 4.3 标准化与除以 255 有什么区别

另一种操作是：

\[
标准化后=(输入-均值)/标准差
\]

通道标准化会为每个通道分别指定均值与标准差，TorchVision 的 `Normalize` 使用这一形式。[官方公式](https://docs.pytorch.org/vision/stable/generated/torchvision.transforms.Normalize.html)

为方便手算，**仅在教学中**取三个通道的均值都为 0.5、标准差都为 0.5：

```text
输入 0   → (0 − 0.5) / 0.5 = −1
输入 0.5 → (0.5 − 0.5) / 0.5 =  0
输入 1   → (1 − 0.5) / 0.5 =  1
```

对应代码：

```python
mean = torch.tensor([0.5, 0.5, 0.5]).reshape(3, 1, 1)
std = torch.tensor([0.5, 0.5, 0.5]).reshape(3, 1, 1)
image_standardized = (image_01 - mean) / std
```

`[3, 1, 1]` 表示每个通道一个数，这个数应用到该通道的所有位置。后续的矩阵部分会详细学习“广播”。

这里 `[0.5, 0.5, 0.5]` 是演示用的设定，**不是 ImparTail 或任意预训练检测器的通用配置**。使用预训练权重时，要读取它要求的颜色顺序、缩放范围、均值和标准差。

有了负数不代表图片坏了。标准化后的张量是模型输入，不再直接用原始 RGB 数字解释颜色。

#### 4.4 常见的完整预处理顺序

```text
读取图片
  → 确认 RGB 或其他颜色约定
  → 按项目要求调整大小
  → 调整为所需维度顺序
  → 转为浮点数
  → 按要求缩放与标准化
  → 加批次维度或组成批次
```

这里有些步骤在库函数中会一起完成，也可能采用不同的顺序。现在要学会逐项检查含义，而不是机械复制。

### 5．图像坐标与张量索引：最容易弄反的地方

#### 5.1 图像中的 x、y

常见图像坐标把左上角作为原点：

```text
(0, 0) ─────────→ x：向右增大
  │
  │
  ↓
  y：向下增大
```

因此：

- x 表示横向位置，对应列。
- y 表示纵向位置，对应行。

#### 5.2 索引顺序通常先行后列

对于 HWC 图片：

```python
image_hwc[y, x, channel]
```

例如“横坐标 x=1、纵坐标 y=0”，是第一行第二列：

```python
image_hwc[0, 1]  # 绿色像素
```

**坐标写 `(x, y)`，张量索引却写 `[y, x]`。**不要因为横坐标叫 x，就把 x 永远放在索引第一位。

对于 CHW 图片，则是：

```python
image_chw[channel, y, x]
```

真实代码里的 `x` 也可能只是变量名，例如 `x = input_tensor`，不一定表示横坐标。要结合上下文判断。

### 6．分类、检测和分割分别在做什么

假设一张图片里有一个人和一个杯子。

| 任务 | 需要回答的问题 | 典型输出 |
| --- | --- | --- |
| 图片分类 | 图片主要属于什么类别？ | 一个或多个类别及分数 |
| 物体检测 | 有哪些物体，分别在哪里？ | 每个物体的类别、框、分数 |
| 语义分割 | 每个像素属于什么类别？ | 每个像素的类别 |
| 实例分割 | 每个像素属于哪个具体物体？ | 类别和每个实例的区域 |

如果图片里有两个杯子，语义分割会把两者的像素都标为“杯子”；实例分割还需要区分“杯子 1”和“杯子 2”。

用教学数据示意一个检测结果：

```python
boxes = torch.tensor([
    [10., 10., 50., 80.],  # 第一个物体的位置
    [40., 30., 60., 50.]   # 第二个物体的位置
])

labels = ["人", "杯子"]
scores = torch.tensor([0.95, 0.87])
```

这些数字由我们手工指定，**不是运行模型得到的预测**。

真实检测器通常还会提供类别编号，例如 `0、1、2`，需要类别表才能翻译成人类名称；有些实现保留某个编号给背景，具体编号不能凭空猜。

置信分数是模型给出的数值；即使输出是 0.95，也不自动意味着“现实中正确率严格等于 95%”。

检测框、标签与像素掩码的区别，可参考 [PyTorch 物体检测与实例分割教程](https://docs.pytorch.org/tutorials/intermediate/torchvision_tutorial.html)。

### 7．物体框：四个数字怎样描述一个矩形

#### 7.1 `xyxy` 格式

一种常见格式是：

```text
[左边 x, 上边 y, 右边 x, 下边 y]
```

记作 \([x_1,y_1,x_2,y_2]\)。例如：

```text
[10, 10, 50, 50]
```

我们在本节使用连续边界坐标约定：

\[
宽=x_2-x_1=40
\]

\[
高=y_2-y_1=40
\]

\[
面积=宽\times高=1600
\]

本节不使用“宽度再加 1”的像素端点约定。某些旧代码会用不同约定，复现时要跟随原代码，不能把两种公式混着用。

#### 7.2 `cxcywh` 格式

另一种常见格式是：

```text
[中心 x, 中心 y, 宽度, 高度]
```

转换公式：

\[
c_x=(x_1+x_2)/2,\qquad c_y=(y_1+y_2)/2
\]

\[
w=x_2-x_1,\qquad h=y_2-y_1
\]

因此：

```text
xyxy：[10, 10, 50, 50]
  → cxcywh：[30, 30, 40, 40]
```

反过来：

\[
x_1=c_x-w/2,\quad y_1=c_y-h/2
\]

\[
x_2=c_x+w/2,\quad y_2=c_y+h/2
\]

**同样四个数字，解释可能完全不同。**读论文或代码时，要先确认框的格式。

#### 7.3 像素坐标与归一化坐标

一张高 H、宽 W 的图片，有些模型会把框坐标缩放为相对位置：

```text
x 类坐标除以 W
y 类坐标除以 H
宽度除以 W
高度除以 H
```

例如高 100、宽 200 的图片：

```text
xyxy：[20, 10, 100, 50]
相对坐标：[0.1, 0.1, 0.5, 0.5]
```

这里的坐标缩放与“颜色值除以 255”是两个不同操作。一个处理位置，一个处理像素强度。

### 8．IoU：两个框有多重合

IoU 中文叫**交并比**，用来比较两个区域的重合程度：

\[
\operatorname{IoU}=\frac{交集面积}{并集面积}
\]

交集是两个框都覆盖的区域。并集是至少被一个框覆盖的区域。

#### 8.1 手算一个完整例子

给定两个 `xyxy` 框：

```text
A = [10, 10, 50, 50]
B = [30, 30, 70, 70]
```

两者宽高都是 40，面积各为 1600。

交集的左上角要选两者中更靠右、更靠下的边界：

```text
交集左边 = max(10, 30) = 30
交集上边 = max(10, 30) = 30
```

交集的右下角要选两者中更靠左、更靠上的边界：

```text
交集右边 = min(50, 70) = 50
交集下边 = min(50, 70) = 50
```

所以：

```text
交集宽 = 50 − 30 = 20
交集高 = 50 − 30 = 20
交集面积 = 20 × 20 = 400

并集面积 = A 面积 + B 面积 − 交集面积
         = 1600 + 1600 − 400
         = 2800

IoU = 400 / 2800 = 1/7 ≈ 0.142857
```

为什么减去一次交集？因为直接把 A、B 的面积相加时，交集被计算了两遍。

#### 8.2 不重合时为什么要取最大值 0

两个框完全分离时，`交集右边 − 交集左边` 可能是负数。负数不是合法宽度，所以使用：

\[
交集宽=\max(0,\min(x_{2A},x_{2B})-\max(x_{1A},x_{1B}))
\]

高度同理。如果宽或高为 0，交集面积为 0，IoU 就为 0。

#### 8.3 对应张量代码

```python
a = torch.tensor([10., 10., 50., 50.])
b = torch.tensor([30., 30., 70., 70.])

intersection_left_top = torch.maximum(a[:2], b[:2])
intersection_right_bottom = torch.minimum(a[2:], b[2:])
intersection_size = (intersection_right_bottom - intersection_left_top).clamp(min=0)
intersection_area = intersection_size.prod()

area_a = (a[2:] - a[:2]).prod()
area_b = (b[2:] - b[:2]).prod()
union_area = area_a + area_b - intersection_area

iou = intersection_area / union_area
print(iou.item())  # 约 0.142857
```

| 写法 | 中文含义 |
| --- | --- |
| `a[:2]` | 取前两个数字，即左上边界 |
| `a[2:]` | 取后两个数字，即右下边界 |
| `torch.maximum` | 对应位置取较大值 |
| `torch.minimum` | 对应位置取较小值 |
| `clamp(min=0)` | 将小于 0 的值改为 0 |
| `prod()` | 把元素相乘，例如宽乘高 |

实际框必须符合该格式，并有合法的宽和高。本节使用正面积合法框，不把 `0/0` 当作正常 IoU。

IoU 完全一致时为 1，没有面积交集时为 0。IoU 只比较区域重合，不能判断类别是否正确，更不能单独判断“人是否拿着杯子”。[TorchVision IoU 定义](https://docs.pytorch.org/vision/stable/generated/torchvision.ops.box_iou.html)

### 9．特征向量：用一串数字描述物体

#### 9.1 原始像素与特征的区别

一张 `[3, 224, 224]` 图片有 \(3\times224\times224=150528\) 个颜色数字。

我们关心的却可能是：有没有人？杯子在哪里？人是不是拿着杯子？模型会把原始像素经过多层运算，变成更适合这些任务的特征。

先看一个**人为定义、可以解释**的描述：

```text
杯子的特征 = [红色程度, 形状接近圆的程度, 宽高比例, 大小]
```

如果用数字表示，就得到一个向量。

真实网络学到的特征通常不是这样逐项命名的。假设：

```python
person_feature = torch.tensor([0.2, -0.4, 0.8, 0.1])
cup_feature = torch.tensor([0.7, 0.3, -0.2, 0.5])
```

我们只知道每个物体用四个数字表示，不能断言“第一个数字代表红色”“第二个数字代表圆形”。这些值只是说明形状，**不是一个训练好的视觉模型提取的真实特征**。

#### 9.2 看懂特征张量形状

假设一帧有 5 个物体，每个物体用 256 个数字表示：

```text
物体特征形状：[5, 256]
              ↑    ↑
           物体数 特征维数
```

第 0 行是一号物体的特征，第 1 行是二号物体的特征。

**256 不是物体类别数，也不是图片宽度。**它是这个模型对每个物体采用的表示长度。

#### 9.3 特征图是什么

如果特征仍保留空间位置，可以得到：

```text
[通道数, 特征图高度, 特征图宽度]
```

例如 `[64, 16, 16]`：在 16×16 个位置上，各保存 64 个特征数值。

这些 64 个通道通常已经不是 RGB 通道了，而是模型学习得到的不同特征响应。物体检测器可以利用整张图的特征图，再提取各个物体区域的特征。

### 10．卷积的核心直觉：在局部区域重复使用同一套权重

现在不需要从零写卷积网络。先理解一次最小计算。

#### 10.1 局部区域与卷积核

假设一个灰度局部区域是：

\[
\begin{bmatrix}1&2\\4&5\end{bmatrix}
\]

有一个 2×2 的权重矩阵，叫卷积核：

\[
\begin{bmatrix}1&0\\0&-1\end{bmatrix}
\]

对应位置相乘，再求和：

\[
1\times1+2\times0+4\times0+5\times(-1)=-4
\]

对应代码：

```python
patch = torch.tensor([[1., 2.], [4., 5.]])
kernel = torch.tensor([[1., 0.], [0., -1.]])
response = (patch * kernel).sum()
print(response.item())  # -4.0
```

这里用的是逐元素乘法 `*`，再求和，不能直接换成矩阵乘法 `@`。

#### 10.2 同一个核在其他位置重复计算

想象一个窗口在图片上移动。在每个位置，取一块相同大小的区域，使用同一组权重相乘求和。每个位置得到一个数，组合起来就是一张输出特征图。

这种“共享权重”意味着：同一种局部模式出现在不同位置时，可以用同一套规则检查它。

这里只演示二维单通道的一次局部运算。真实 RGB 卷积还会在输入通道上求和、可加入偏置，并使用多个卷积核产生多个输出通道。PyTorch `Conv2d` 的运算不把卷积核翻转，严格说是互相关；深度学习里通常也称为卷积。[官方运算定义](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Conv2d.html)

#### 10.3 核的权重怎么得到

上面 `[1, 0; 0, -1]` 是我们人为指定的教学权重。真实网络里的许多卷积核权重由训练学习：

```text
权重影响特征
  → 特征影响预测
  → 预测影响损失
  → backward() 算出损失对权重的梯度
  → 优化器更新权重
```

它与 `03_手动训练_示例.py` 中的 `prediction = w × x` 是同一个训练原则，只是从一个参数扩展到了很多参数。

早期层常能响应简单局部模式，后续层组合更复杂的信息。但不能把任意卷积核都直接叫“杯子检测器”，也不能说某一层必然只负责某种人类命名的特征。

### 11．从图片到场景图：这些知识怎样连起来

#### 11.1 场景图不仅要检测物体

假设图片里有一个人、一只杯子和一张桌子。

物体检测回答：

```text
有什么：人、杯子、桌子
在哪里：每个物体的边界框
```

场景图还要回答：

```text
人 — 拿着 → 杯子
杯子 — 在上方 → 桌子
```

一个关系通常写为三元组：

```text
(主语物体, 关系, 宾语物体)
```

主语和宾语是关系中的角色，不代表图片中一定出现自然语言句子。

#### 11.2 一个常见的概念流程

```text
图片张量
  → 提取整张图的视觉特征
  → 得到物体框、物体类别和物体特征
  → 构造需要研究的物体对
  → 预测每对物体的关系
  → 汇总为节点与边
```

比如针对“人、杯子”这一对，模型可以结合人特征、杯子特征、相对位置以及二者共同区域的视觉信息，预测关系类别。

这是一张帮助理解的概念流程，不意味着所有场景图模型都按完全相同的顺序实现；有些方法把多个任务联合建模。

#### 11.3 静态与动态

| 方向 | 输入 | 还要考虑什么 |
| --- | --- | --- |
| 静态场景图 | 一张图片 | 当前图片里物体及关系 |
| 动态场景图 | 一段视频 | 各帧关系与跨帧时间信息 |

视频可以看作按时间排列的图片：

```text
第 1 帧：人 — 看着 → 杯子
第 2 帧：人 — 拿着 → 杯子
第 3 帧：人 — 放下 → 杯子
```

不能只检查每一帧的颜色而忽略时间。例如“拿起”和“放下”可能需要动作前后变化才能区分。

如果每帧都是 CHW，一种视频张量排列可以是 `[帧数, 通道, 高度, 宽度]`。有多个视频时，可以再加批次维度。但真实项目也可能采用其他维度顺序或按列表存储，要按该项目代码理解。

#### 11.4 给定物体信息时，任务难度不同

| 任务 | 已给定的信息 | 模型需要预测 |
| --- | --- | --- |
| PredCls，关系分类 | 真实物体框和物体类别 | 物体间关系 |
| SGCls，场景图分类 | 真实物体框 | 物体类别和关系 |
| SGDet，场景图检测 | 原始图片／视频帧 | 物体框、物体类别和关系 |

“真实”指数据标注提供的信息，也常叫“真值”。PredCls 不是模型不用视觉信息，而是它已知物体框和类别，可以把重点放在关系预测。

#### 11.5 和 ImparTail 的学习目标连接

你现在学这些知识，是为了之后读懂：

```text
视频数据
  → 物体与关系特征
  → 基线模型产生关系预测
  → 用关系标注计算损失
  → 按训练策略处理损失
  → 反向传播并更新参数
```

关于 ImparTail 的具体掩码策略，要以它的论文与实现为准，本节不把任意教学掩码当作论文完整算法。[论文入口](https://arxiv.org/abs/2411.13059) · [官方代码](https://github.com/rohithpeddi/ImparTail)

“预训练检测器”表示检测器已经在某些数据上学到了一组权重，可以加载使用或继续训练。它不等于大语言模型。预训练描述的是训练状态；大语言模型描述的是模型类型与规模，两者不是同一分类标准。

### 12．常见误解，一次纠正

| 误解 | 正确理解 |
| --- | --- |
| `[3, 32, 64]` 一定是三张图片 | 如果按 CHW，它是一张三通道图片 |
| `.float()` 自动把数值变成 0～1 | 它只改变类型，缩放要另做 |
| `permute` 会给图片换颜色 | 正确使用时只改变维度顺序 |
| `reshape` 和 `permute` 都能随便用来转 CHW | 转换轴的含义要用维度排列，不能只改尺寸 |
| 图片坐标 `(x, y)` 就索引 `[x, y]` | HWC 的位置索引是 `[y, x]` |
| 物体框四个数的含义都相同 | 要区分 xyxy、cxcywh 等格式 |

| 特征第一个数一定是颜色 | 网络特征通常不能逐维这样解释 |
| 分类器找到杯子，就知道杯子在哪 | 图片分类不必输出位置，检测才要求位置 |
| 有预训练模型就等于用了大语言模型 | 预训练检测器可以是常规视觉模型 |

### 1．标量、向量、矩阵与张量

#### 1.1 四个名字是怎样联系起来的

| 名称 | 直观理解 | 例子 | 对应形状 |
|---|---|---|---|
| 标量 | 一个数 | `3.0` | `[]` |
| 向量 | 按顺序排列的一串数 | `[1., 2., 3.]` | `[3]` |
| 矩阵 | 两个方向排列的数表 | 两行三列 | `[2, 3]` |
| 张量 | 统一表示这些数据，也能有更多维度 | 三通道图片 | `[3, 高度, 宽度]` |

PyTorch 中，标量也可以是张量，所以“张量”不是只指三维及以上的数据。

```python
import torch

scalar = torch.tensor(3.0)              # 标量
vector = torch.tensor([1., 2., 3.])    # 向量
matrix = torch.tensor([
    [1., 2., 3.],
    [4., 5., 6.]
])                                    # 矩阵

print(scalar.shape)  # torch.Size([])
print(vector.shape)  # torch.Size([3])
print(matrix.shape)  # torch.Size([2, 3])
```

#### 1.2 “有几维”和“每一维有多长”不是同一个问题

```python
print(matrix.ndim)   # 2：有两个维度
print(matrix.shape)  # [2, 3]：第一个维度长 2，第二个长 3
print(matrix.numel())  # 6：一共有六个元素
```

有时说“一个 256 维特征向量”，这里的“256 维”是指有 256 个分量。它在 PyTorch 中仍然是一个形状为 `[256]` 的**一维张量**。要根据上下文区别数学里的特征维数与张量的维度数量。

#### 1.3 相同的数据量，不代表相同的形状

```text
[4]      四个数的一维张量
[1, 4]   一行四列
[4, 1]   四行一列
```

它们都有四个元素，但计算时的行为可能不同。

```python
values = torch.tensor([1., 2., 3., 4.])
print(values.shape)               # [4]
print(values.unsqueeze(0).shape)  # [1, 4]：在第 0 维增加长度为 1 的维度
print(values.unsqueeze(1).shape)  # [4, 1]：在第 1 维增加长度为 1 的维度
```

不要把 `[4, 1]` 直接当作 `[4]`。后面第 5 节会看到一个不一定报错、却会让训练错掉的例子。

#### 1.4 把形状读成一句话

```text
[8, 256]       8 个样本，每个样本有 256 个特征
[8, 3, 32, 64] 8 张图片，每张有 3 个通道，高 32、宽 64
[10, 3]        10 个样本，每个样本输出 3 个类别分数
```

**形状本身不包含“样本”“通道”等语义。**这些含义来自代码与约定，所以读论文代码时要记下每个维度代表什么。

### 2．向量：特征怎样参加计算

#### 2.1 向量加减与乘一个数

设：

```text
a = [1, 2, 3]
b = [4, 5, 6]
```

按对应位置计算：

```text
a + b = [5, 7, 9]
a - b = [-3, -3, -3]
2 × a = [2, 4, 6]
```

```python
a = torch.tensor([1., 2., 3.])
b = torch.tensor([4., 5., 6.])

print(a + b)
print(a - b)
print(2 * a)
```

现实视觉模型中的特征向量，通常由网络学出来。某一维不一定能解释成“红色程度”或“物体大小”。下面的简化例子只是帮助理解计算。

#### 2.2 点积：对应位置相乘，然后相加

点积写作：

\[
\mathbf a\cdot\mathbf b=a_1b_1+a_2b_2+a_3b_3
\]

这不是一个新奇操作，就是“乘完再求和”：

```text
[1, 2, 3] · [4, 5, 6]
= 1×4 + 2×5 + 3×6
= 32
```

```python
print(torch.dot(a, b))  # tensor(32.)
print((a * b).sum())    # 同样是 32
```

看清这两个结果：

```python
a * b  # [4, 10, 18]：逐元素相乘，仍然有三个数
a @ b  # 32：两个一维向量的点积，结果是一个数
```

`@` 在二维矩阵上表示矩阵乘法，在两个一维向量上表示点积。高维批量运算会有进一步规则，这里先掌握这两种。

#### 2.3 为什么模型常用点积

把输入写成 `[x1, x2, x3]`，给每个输入一个权重 `[w1, w2, w3]`：

\[
预测=w_1x_1+w_2x_2+w_3x_3
\]

这就是输入向量与权重向量的点积。三个权重决定三个输入怎样影响预测。

例如：

```text
输入 = [1, 2, 3]
权重 = [1, 0, 1]
预测 = 1×1 + 2×0 + 3×1 = 4
```

第二个输入的权重是零，所以这次不影响输出。训练就是用数据逐渐调整这些权重。

#### 2.4 模长：向量的长度（扩展）

二维向量 `[3, 4]` 可以想成“向右 3、向上 4”。从起点到终点的直线长度是：

\[
\|\mathbf v\|=\sqrt{3^2+4^2}=5
\]

```python
v = torch.tensor([3., 4.])
print(torch.linalg.vector_norm(v))  # 5
```

更长的向量也一样：各分量平方、相加、开平方。它能帮助度量特征大小或梯度大小。

点积有时用于比较特征，但会受模长影响。向量大不一定就更相似；后续学“余弦相似度”时才会明确处理这一点。

### 3．矩阵乘法：把多个点积一次算出来

#### 3.1 先判断能不能乘

二维矩阵乘法规则：

\[
[样本数,输入特征数]\ @\ [输入特征数,输出特征数]
\longrightarrow[样本数,输出特征数]
\]

简记为：

```text
[m, n] @ [n, p] → [m, p]
          ↑
     中间两个长度要相同
```

例如 `[2, 3] @ [3, 2]` 可以计算，结果是 `[2, 2]`。`[2, 3] @ [2, 3]` 不满足条件。

#### 3.2 一格一格手算

输入矩阵与权重矩阵：

```text
X = [[1, 2, 3],       W = [[1, 0],
     [4, 5, 6]]            [0, 1],
                          [1, 1]]
```

结果的每一格等于：**左矩阵的一行，与右矩阵的一列，做点积。**

```text
第1行第1列：1×1 + 2×0 + 3×1 = 4
第1行第2列：1×0 + 2×1 + 3×1 = 5
第2行第1列：4×1 + 5×0 + 6×1 = 10
第2行第2列：4×0 + 5×1 + 6×1 = 11

X @ W = [[ 4,  5],
         [10, 11]]
```

```python
X = torch.tensor([[1., 2., 3.], [4., 5., 6.]])
W = torch.tensor([[1., 0.], [0., 1.], [1., 1.]])

result = X @ W
print(result)
print(result.shape)  # [2, 2]
```

对应模型：两条输入，每条三个特征；用两组权重产生两个输出。这两组权重保存在 `W` 的两列里。

#### 3.3 矩阵乘法不等于逐元素乘法

```python
A = torch.tensor([[1., 2.], [3., 4.]])
B = torch.tensor([[5., 6.], [7., 8.]])

print(A * B)  # [[5, 12], [21, 32]]
print(A @ B)  # [[19, 22], [43, 50]]
```

`*` 对应位置相乘；`@` 把一行与一列的乘积加起来。看代码时，先看清运算符。

### 4．转置、偏置与线性层

#### 4.1 转置把行列交换

```text
X = [[1, 2, 3],      Xᵀ = [[1, 4],
     [4, 5, 6]]            [2, 5],
                          [3, 6]]

形状：[2, 3] → [3, 2]
```

```python
print(X.T)  # 这里 X 是二维矩阵
```

上标 `T` 表示转置。对图片等高维张量，应该明确要交换哪两个维度，不要直接把 `.T` 当成万能维度调整方法；图像通道调整会用到 `permute(...)`。

#### 4.2 线性层是“加权求和，再加偏置”

一个输入时：

\[
y=wx+b
\]

多个样本、多个输入时，可以写成：

\[
Y=XW+b
\]

本节数学写法中，`W` 的形状是 `[输入特征数, 输出特征数]`。偏置 `b` 为每个输出增加一个可学习的偏移。

```python
b = torch.tensor([0.5, -0.5])
Y = X @ W + b
print(Y)  # [[4.5, 4.5], [10.5, 10.5]]
```

两行共享同一组权重和偏置，并不是每个样本各自拥有一套参数。

#### 4.3 PyTorch 的权重保存方向要单独记住

```python
layer = torch.nn.Linear(3, 2)
```

含义是“每个样本输入三个特征，输出两个特征”。

**PyTorch 的 `layer.weight` 实际保存为 `[输出特征数, 输入特征数]`，因此本例是 `[2, 3]`。**它的计算等价于：

```python
output = X @ layer.weight.T + layer.bias
```

这与上一节数学写法并不矛盾：上一节的 `W` 对应这里的 `layer.weight.T`。注意自己正在使用哪个约定。该形状和计算规则见 [PyTorch 官方线性层文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.Linear.html)。

```python
layer = torch.nn.Linear(3, 2)
with torch.no_grad():
    layer.weight.copy_(W.T)
    layer.bias.copy_(b)

print(layer(X))  # 与 X @ W + b 相同
```

`copy_` 把右边数值复制到现有参数中；这里用于设置一个可手算的示例，不是每次训练都要手动设置。

### 5．广播：形状不相同时，为什么有时还能相加

#### 5.1 一个数能加到所有元素上

```python
X + 10
```

直观上等于“每个位置都加 10”。PyTorch 按广播规则扩展参与计算的形状，不需要你手写循环。

#### 5.2 一个偏置向量能加到每行

```text
[[ 4,  5],   + [0.5, -0.5]
 [10, 11]]

→ [[4.5, 4.5],
   [10.5, 10.5]]
```

形状是 `[2, 2] + [2]`，右边的两个偏置分别加到每行的两列。

常用判断方法：**从最右边的维度向左对齐，两边长度相同，或者至少一边为 1，才能广播。**缺失的前导维度可以看成 1。

#### 5.3 一个重要陷阱：`[4, 1]` 与 `[4]`

设预测有四行，每行一个数：

```python
prediction = torch.tensor([[1.], [2.], [3.], [4.]])  # [4, 1]
target = torch.tensor([1., 2., 3., 4.])              # [4]

error = prediction - target
print(error.shape)  # [4, 4]，不是希望的 [4, 1]
```

第一行竟然成了 `[1-1, 1-2, 1-3, 1-4]`。每个预测都与四个目标相减，而不是只和对应目标比较。

```text
error = [[ 0, -1, -2, -3],
         [ 1,  0, -1, -2],
         [ 2,  1,  0, -1],
         [ 3,  2,  1,  0]]
```

因此：

```python
wrong_loss = ((prediction - target) ** 2).mean()
print(wrong_loss)  # 2.5：明明每个预测都正确，却算出非零损失
```

修正为相同形状：

```python
target = target.unsqueeze(1)  # [4] → [4, 1]
loss = ((prediction - target) ** 2).mean()
print(loss)  # 0
```

**计算回归损失前，先打印预测和目标的形状，确认元素一一对应。**分类损失有自己的形状约定，不能套用“所有损失输入都必须同形状”这个结论。

### 6．均值、方差与标准化（先懂用途）

#### 6.1 均值就是平均数

\[
\text{均值}=\frac{所有数相加}{数的个数}
\]

```text
数据：[1, 2, 3]
均值：(1+2+3)/3 = 2
```

```python
values = torch.tensor([1., 2., 3.])
print(values.mean())  # 2
```

在矩阵里，`mean(dim=...)` 与之前的 `sum(dim=...)` 类似，只是把求和换成平均。

```python
print(X.mean(dim=0))  # 每列平均：[2.5, 3.5, 4.5]
print(X.mean(dim=1))  # 每行平均：[2., 5.]
```

#### 6.2 方差衡量数值分散程度（扩展）

本节使用“总体方差”：每个数减去均值、平方，然后平均。

\[
\text{方差}=\frac{(1-2)^2+(2-2)^2+(3-2)^2}{3}=\frac{2}{3}
\]

```python
mean = values.mean()
variance = ((values - mean) ** 2).mean()
print(variance)  # 约 0.6667
```

标准差是方差的平方根。标准化常写作：

\[
z=\frac{x-均值}{标准差}
\]

它把数据平移到均值附近，再调整尺度。你在图像预处理里遇到“减均值、除标准差”时，可以从这里理解。

使用这条除法公式时，标准差必须大于零。所有数据相同时标准差为零，不能直接照搬这个除法。

**除以 255** 是把常见像素值换到 `[0,1]`；**减均值、除标准差** 是进一步的标准化。它们是两个操作。

PyTorch 计算方差的函数会有不同校正约定，所以初学时可以先用上面的显式公式，避免与分母为 `n-1` 的样本方差混淆。

### 7．函数与导数：输出随输入怎样变化

#### 7.1 函数就是一条计算规则

\[
y=x^2
\]

输入 `x=2`，输出 `y=4`。输入 `x=3`，输出 `y=9`。

函数值回答“现在输出是多少”。导数回答“在这个位置，输入稍微增加一点，输出大约怎样变化”。

#### 7.2 先用具体数字理解变化率

在 `x=2` 附近，从 2 增加到 2.01：

```text
原输出 = 2² = 4
新输出 = 2.01² = 4.0401
输入变化 = 0.01
输出变化 = 0.0401
平均变化率 = 0.0401 / 0.01 = 4.01
```

让输入变化越来越小，这个比值会靠近 4。这就是 `x²` 在 `x=2` 时导数为 4 的直觉。

\[
\frac{dy}{dx}=2x
\]

符号 `dy/dx` 表示“`y` 对 `x` 的导数”，不是在这里把两个普通数相除。

#### 7.3 现阶段常用的三条规则

| 函数 | 导数 | 直觉 |
|---|---|---|
| `y=常数` | `0` | 输入变了，输出不变 |
| `y=ax+b` | `a` | 输入增加一点，输出按 `a` 倍变化 |
| `y=x²` | `2x` | 不同位置有不同变化率 |

例如 `y=2*x²+5*x`，导数为 `4*x+5`。在 `x=3` 时，函数值是 33，导数是 17。

不要把“函数值”和“导数”混成同一个数。

### 8．偏导与梯度：每个参数分别要怎么改

#### 8.1 有两个输入时，先固定另一个

\[
L=a^2+b^2
\]

求 `L` 对 `a` 的偏导：把 `b` 当作固定数字，结果为 `2a`。求 `L` 对 `b` 的偏导：把 `a` 当作固定数字，结果为 `2b`。

“偏导”中的“偏”，可以先理解成“只看其中一个输入的变化”。数学符号使用 `∂`：

\[
\frac{\partial L}{\partial a}=2a,\qquad
\frac{\partial L}{\partial b}=2b
\]

当 `[a,b]=[2,3]`：

```text
损失 L = 2²+3² = 13
梯度 = [4,6]
```

**梯度把对各个输入的偏导排列在一起。**它的形状与对应的可学习参数相同。

```python
parameters = torch.tensor([2., 3.], requires_grad=True)
loss = (parameters ** 2).sum()
loss.backward()

print(loss.item())  # 13
print(parameters.grad)  # [4, 6]
```

这里 `loss` 是一个总数，但两个参数各自有一个梯度。

#### 8.2 梯度不是“模型输出”，也不是“更新后的参数”

| 名称 | 回答的问题 |
|---|---|
| 预测值 | 模型现在给出什么答案？ |
| 损失 | 预测和目标差多少？ |
| 梯度 | 这个位置附近，参数变化怎样影响损失？ |
| 更新后的参数 | 按更新规则调整后，参数变成多少？ |

`loss.backward()` 计算并保存梯度；它不会自动更新参数。

### 9．链式法则：把你第三课的梯度一步一步算出来

你学过：

```python
prediction = w * x
loss = (prediction - target) ** 2
loss.backward()
```

设输入 `x=2`，目标 `target=6`，参数 `w=1`。输入和目标固定，只有 `w` 需要学习。

#### 9.1 把计算拆成三个小步骤

\[
p=wx,\qquad e=p-t,\qquad L=e^2
\]

| 符号 | 中文含义 | 具体数值 |
|---|---|---:|
| `p` | 预测值 | `1×2=2` |
| `e` | 预测误差 | `2-6=-4` |
| `L` | 平方损失 | `(-4)²=16` |

计算关系：

```text
w → 乘以 x → 预测 p → 减目标 t → 误差 e → 平方 → 损失 L
```

#### 9.2 求每一步的导数

损失对误差：

\[
\frac{dL}{de}=2e=-8
\]

误差对预测：

\[
\frac{de}{dp}=1
\]

预测对参数：

\[
\frac{dp}{dw}=x=2
\]

**链式法则就是沿着这条依赖路径，把局部导数相乘。**

\[
\frac{dL}{dw}
=\frac{dL}{de}\times\frac{de}{dp}\times\frac{dp}{dw}
=(-8)\times1\times2=-16
\]

合起来得到公式：

\[
\boxed{\frac{dL}{dw}=2(wx-t)x}
\]

#### 9.3 PyTorch 如何对应这些步骤

```python
w = torch.tensor(1.0, requires_grad=True)
x = torch.tensor(2.0)
target = torch.tensor(6.0)

prediction = w * x
loss = (prediction - target) ** 2

print(w.grad)  # None：还没计算梯度
loss.backward()
print(w.grad.item())  # -16
```

`requires_grad=True` 让涉及参数的运算被跟踪。`backward()` 根据记录的依赖关系反向计算，结果保存在 `w.grad`。`item()` 只是读取单元素张量的普通数值，不负责求导。自动求导机制见 [PyTorch 官方教程](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)。

#### 9.4 输入固定，为何还要乘上输入 x

“固定”表示这次不学习 `x`，并不表示 `x` 对梯度没有影响。改变 `w` 时，预测 `wx` 的变化速度是 `x`，所以链式法则里仍然有这个乘数。

如果输入为 10，参数增加 0.01，预测会增加 0.1；如果输入为 2，参数增加 0.01，预测只增加 0.02。

### 10．梯度下降：算出梯度后，怎样实际更新

#### 10.1 更新规则

\[
新参数=旧参数-学习率\times梯度
\]

学习率 `learning_rate` 控制本次移动的步长。对多个参数，也分别使用各自的梯度应用这条规则。

从 `w=1`、梯度 `-16` 开始，学习率为 0.1：

```text
新参数 = 1 - 0.1×(-16) = 2.6
新预测 = 2.6×2 = 5.2
新损失 = (5.2-6)² = 0.64
```

这次损失从 16 降到 0.64。**梯度为负时，减去梯度会使参数增大。**“下降”指期望降低损失，参数本身未必变小。

#### 10.2 学习率过大可能让损失上升

在完全相同的初始状态，改用学习率 0.5：

```text
新参数 = 1 - 0.5×(-16) = 9
新预测 = 9×2 = 18
新损失 = (18-6)² = 144
```

方向根据当前局部梯度确定，但一下跨太远，就越过了好的位置。不是执行了 `backward()` 和更新语句，损失就一定下降。

#### 10.3 连接到你已经学过的代码

```python
loss.backward()  # 先求导

with torch.no_grad():
    w -= 0.1 * w.grad  # 使用求导结果更新参数
    new_prediction = w * x
    new_loss = (new_prediction - target) ** 2

w.grad.zero_()  # 清除已经使用的梯度
```

`torch.no_grad()` 不记录块内的运算用于后续求导，让你可以直接修改需要求导的叶子参数。它不删除原来的 `w.grad`，也不会永久关闭参数的求导功能。

更新参数后，旧的 `prediction` 和 `loss` 不会自动刷新，所以必须重新计算新预测、新损失。这里的新损失仅用来观察效果；下一轮训练要在正常跟踪运算的环境里重新预测、计算损失。

`w.grad.zero_()` 把梯度清零，不会把参数清零。默认情况下，新的梯度会累加到原梯度里；普通训练每次更新后要清除旧梯度，后面学梯度累积时会有不同用法。

### 11．均方误差：多个样本的回归损失

单个样本使用平方误差：

\[
L=(预测-目标)^2
\]

多个标量预测，常把每个平方误差取平均，叫**均方误差**，代码中常写 `MSE`。

\[
L=\frac1n\sum_{i=1}^n(预测_i-目标_i)^2
\]

这里 `Σ` 表示求和，`i` 是样本编号，`n` 是样本数。

```text
预测：[2, 4]
目标：[1, 6]
误差：[1, -2]
误差平方：[1, 4]
均方误差：(1+4)/2 = 2.5
```

```python
prediction = torch.tensor([2., 4.], requires_grad=True)
target = torch.tensor([1., 6.])

loss = torch.nn.functional.mse_loss(prediction, target)
loss.backward()

print(loss.item())  # 2.5
print(prediction.grad)  # [1, -2]
```

为什么梯度不是 `[2, -4]`？因为损失取了平均，还要除以元素数 2：

\[
\frac{\partial L}{\partial 预测_i}=\frac{2(预测_i-目标_i)}n
\]

本例每个样本只有一个输出，`n` 就是总元素数。多输出情况中，默认 `MSELoss` 是对全部输出元素平均。

把 `.mean()` 改成 `.sum()`，损失和梯度尺度都会改变。论文复现时要核对损失是求和、平均，还是按未被屏蔽的元素重新归一化。

### 12．分类：分数、概率、真实类别与损失

回归是在预测一个数；分类是在若干类别中作判断。场景图中的关系可以被表示成类别，例如“拿着”“看着”“其他”。这里的三分类只是教学例子。

#### 12.1 原始分数不是概率

模型可以先输出：

```text
类别编号：  0      1      2
类别名称：拿着   看着   其他
原始分数： 2      1      0
```

原始分数常写作 `logits`。它们可以是负数，也不要求加起来等于 1。分数最高的类别是当前预测类别。

```python
logits = torch.tensor([[2., 1., 0.]])  # 一条样本，三个类别：[1, 3]
predicted_class = logits.argmax(dim=1)
print(predicted_class)  # [0]
```

`argmax` 取“最大值所在的编号”，不是取最大值本身。

#### 12.2 softmax 把一组分数换成一组概率

\[
p_i=\frac{e^{z_i}}{e^{z_0}+e^{z_1}+e^{z_2}}
\]

`z` 是原始分数，`e^z` 是指数运算，`p` 是转换后的概率。第一遍只需要记住：每个值在 0 与 1 之间，同一条样本的类别概率加起来等于 1。

```text
原始分数：[2, 1, 0]
指数值约：[7.389, 2.718, 1]
总和约：11.107
概率约：[0.6652, 0.2447, 0.0900]
```

```python
probabilities = torch.softmax(logits, dim=1)
print(probabilities)
print(probabilities.sum(dim=1))  # [1]
```

对于 `[样本数, 类别数]`，`dim=1` 表示在每条样本的类别维度内转换。用错成 `dim=0`，就会在不同样本之间计算，而不是在类别之间计算。

这些数是模型给出的概率估计，不代表现实中必然正确，也不保证经过良好的置信度校准。

#### 12.3 交叉熵让正确类别获得更高概率

对于“每条样本一个真实类别”的简单情形，损失为：

\[
L=-\ln(p_{正确类别})
\]

`ln` 是自然对数。先看数值：正确类别概率越接近 1，损失越接近 0；概率很低时，损失很大。

**指数与对数怎样读（扩展）：**`e` 是约等于 2.71828 的数学常数。`e^z` 读作“e 的 z 次方”，例如 `e^0=1`、`e^1≈2.7183`、`e^2≈7.3891`。`exp(z)` 就是另一种写 `e^z` 的方式。

`ln(a)` 问的是“e 的多少次方等于 a”，所以它与指数互为反向操作。例如 `ln(1)=0`，因为 `e^0=1`。当 a 在零和一之间，`ln(a)` 为负，因此损失前面加负号后为正。

| 正确类别概率 | `-ln(概率)` | 怎样理解 |
| --- | ---: | --- |
| 1 | 0 | 概率完全给到真实类别 |
| 0.5 | 约 0.6931 | 真实类别只获得一半概率 |
| 0.1 | 约 2.3026 | 给真实类别的概率很低 |

第一遍会代入数字比较大小即可，不需要先学对数的完整证明。实际损失函数直接接收原始分数，内部使用稳定算法计算。

如果真实类别为 0，上面的例子：

```text
真实类别概率 ≈ 0.6652
交叉熵 = -ln(0.6652) ≈ 0.4076
```

```python
logits = torch.tensor([[2., 1., 0.]], requires_grad=True)
target = torch.tensor([0], dtype=torch.long)

loss = torch.nn.functional.cross_entropy(logits, target)
loss.backward()

print(loss.item())  # 约 0.4076
print(logits.grad)  # 约 [-0.3348, 0.2447, 0.0900]
```

正确类别的梯度为负，按梯度下降更新时有提高其分数的趋势；其他类别的梯度为正，有降低其分数的趋势。

**这个常用类别编号写法的输入约定：**

```text
logits：[样本数, 类别数]，浮点数，传入原始分数
target：[样本数]，torch.long，值为 0～类别数减一的类别编号
```

因此普通三分类标签可以是 `[0, 2, 1]`，不是把类别编号写成浮点数，也不是默认必须手写独热向量。独热向量是用 `[1,0,0]` 这类形式标出一个类别的写法；本例直接使用类别编号即可。

**训练时不要先 `softmax` 再把概率传给 `cross_entropy`。**该函数会在内部处理相应的运算；手动 `softmax` 可以用来显示概率，但损失仍直接接收原始分数。这里讲的是最常用的类别编号目标方式，PyTorch 也支持概率形式的目标等其他设置。见 [官方交叉熵文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)。

### 13．二分类与多标签：sigmoid 和二元交叉熵

#### 13.1 sigmoid 把每个分数单独换成概率

\[
\sigma(z)=\frac1{1+e^{-z}}
\]

```text
原始分数 0 → 概率 0.5
原始分数 2 → 概率约 0.8808
原始分数 -2 → 概率约 0.1192
```

```python
logits = torch.tensor([-2., 0., 2.])
print(torch.sigmoid(logits))
```

sigmoid 对各个元素独立计算，结果不要求相加等于 1。

| 任务 | 一个样本的标签含义 | 常见处理 |
|---|---|---|
| 单标签多分类 | 三种关系中只选择一种 | 原始分数＋交叉熵；显示概率时用 softmax |
| 二分类 | 是否存在某个关系 | 原始分数＋二元交叉熵；显示概率时用 sigmoid |
| 多标签分类 | 同一物体对可同时有多个关系 | 每个标签单独判断；常用 sigmoid 与二元交叉熵 |

真实场景图模型可能对不同关系组使用不同方式；读代码时需要看标注定义和实际损失，不能只凭“场景图”三个字决定。

#### 13.2 二元交叉熵怎样计算

令 `t` 是 0 或 1 的真实标签，`p` 是关系存在的概率：

\[
L=-[t\ln p+(1-t)\ln(1-p)]
\]

当 `t=1`，只剩 `-ln(p)`；当 `t=0`，只剩 `-ln(1-p)`。

如果原始分数为 0，概率为 0.5，真实标签为 1：

```text
损失 = -ln(0.5) ≈ 0.6931
```

```python
logit = torch.tensor([0.0], requires_grad=True)
target = torch.tensor([1.0])  # 这里用浮点目标，形状与原始分数相同

loss = torch.nn.functional.binary_cross_entropy_with_logits(logit, target)
loss.backward()

print(loss.item())  # 约 0.6931
print(logit.grad)  # [-0.5]
```

函数名中的 `with_logits` 表示接收原始分数，并在内部处理 sigmoid 与损失计算；不要先对它的输入调用 sigmoid。输入与目标形状相同，目标常用浮点型 0／1。[PyTorch 官方二元交叉熵文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.BCEWithLogitsLoss.html)

#### 13.3 三种损失的输入速查

| 常见用法 | 模型输出 | 目标 | 主要用途 |
|---|---|---|---|
| `mse_loss` | 浮点预测，与目标同形状 | 浮点数值 | 回归 |
| `cross_entropy` | `[N,C]` 原始分数 | `[N]` 整数类别，`long` | 单标签多分类 |
| `binary_cross_entropy_with_logits` | 原始分数 | 同形状浮点 0／1 | 二分类、多标签分类 |

`N` 表示样本数，`C` 表示类别数。表中是本课的简单情况，图像分割等任务还会有额外维度。

### 14．常见误区：遇到问题时先检查这里

| 误解或问题 | 正确理解／检查方法 |
|---|---|
| `[4]` 和 `[4,1]` 元素数相同，所以随便用 | 广播行为不同；先打印形状 |
| `*` 和 `@` 都是乘法，所以结果一样 | 一个逐元素乘，一个执行点积或矩阵乘法 |
| `nn.Linear(3,2)` 的权重一定是 `[3,2]` | PyTorch 保存 `[2,3]`，计算时使用转置 |
| `.item()` 会求导 | 它只是把单元素张量读成普通数值 |
| `backward()` 后参数会自动更新 | 它只计算梯度，更新还需要手写规则或优化器 |
| 用完梯度就自动消失 | 默认会保留并累加；普通训练要清除旧梯度 |
| 清除梯度会把权重变成零 | 清除的是 `.grad`，不是参数本身 |
| 学习率越大，学得越快越好 | 可能跨过好的位置，让损失增大 |
| softmax 输出一定是真实可靠的置信度 | 它是模型的概率估计，仍可能预测错误或过度自信 |
| 所有关系类别都适合 softmax | 若允许同时有多个标签，要检查多标签处理方式 |
| 交叉熵输入要先 softmax | 常用 `cross_entropy` 直接接收原始分数 |

## 第三步·第三部分：注意力、场景图，以及与 ImparTail 的连接

这一部分的目标是把已经学过的“张量、矩阵乘法、分类、损失和梯度”连成一条线。读完后，你应该能解释：视频中的物体如何得到特征，特征怎样结合其他物体和其他帧的信息，关系分类器怎样生成场景图，ImparTail 又改变了训练中的哪一步。

这里先学习必要的基础，不要求你立刻背完整个 Transformer，也不要求你先装 STTran 的训练环境。配套练习只使用已有 PyTorch 环境，在处理器上运行，不下载图片、数据集和模型。

### 一、先分清物体、类别、特征和参数

假设一张图片中有一个人和一个杯子。模型通常会处理几种不同的数据：

| 数据 | 例子 | 作用 |
| --- | --- | --- |
| 物体框 | `[左, 上, 右, 下]` | 说明物体在图片中的位置 |
| 物体类别 | “人”“杯子”对应的类别编号 | 说明模型判断它是什么 |
| 物体特征 | `[0.2, -0.7, 1.3, ...]` | 保存模型提取的数值表示 |
| 模型参数 | 权重矩阵、偏置 | 通过训练学到如何计算这些表示和预测 |

**特征向量不等于类别标签。**类别通常是一个编号；特征往往是一串浮点数，用于后续计算。

例如，两个物体各有四个特征数，可以排成：

```python
features = torch.tensor([
    [0.2, -0.7, 1.3, 0.1],  # 第一个物体的特征
    [0.6,  0.4, 0.2, 0.9]   # 第二个物体的特征
])
```

形状为 `[2, 4]`，表示“两个物体，每个物体四个数”。

这里的四个数只是教学示例，**不能直接把第一维叫‘红色程度’，第二维叫‘杯子程度’**。真实模型中的特征通常由网络学到，一个维度未必对应一个能直接命名的概念。

你也不会在真实项目中手工输入每个物体的特征。预训练检测器和特征提取网络会根据图片计算它们；关系模型继续处理这些输出。

#### 为什么不能仅靠物体类别判断关系

“人”和“杯子”这两个类别，可以对应很多情况：

- 人拿着杯子。
- 人看着杯子。
- 杯子放在人的旁边。
- 人没有接触杯子。

只知道“人”和“杯子”，无法确定当前关系。模型还需要外观、位置、局部区域、其他物体和时间变化等信息。

**分类标签回答‘是什么’，关系模型还要回答‘它们正在怎样相互作用’。**

### 二、注意力要解决什么问题

一个物体或者一组物体关系，在单独观察时可能不够明确。注意力让当前表示根据需要，结合其他表示中的信息。

比如在视频里，一个杯子在某帧被手遮住。附近帧中“手逐渐靠近杯子”的信息，可能帮助判断当前的接触关系。

数学上，最基础的注意力可以理解成：

```text
给每一份信息算一个权重
      ↓
把信息乘上对应权重
      ↓
相加，得到融合后的新表示
```

你已经学过矩阵乘法，注意力并不是凭空出现的新运算。它的主要计算就是矩阵乘法、缩放、软最大值和加权求和。

### 三、查询、键和值分别是什么

论文和代码中常用 `Q`、`K`、`V` 三个字母：

| 写法 | 中文 | 用来理解的类比 |
| --- | --- | --- |
| Q：Query | 查询 | 当前表示想获取什么信息 |
| K：Key | 键 | 每份候选信息提供什么匹配线索 |
| V：Value | 值 | 匹配后真正参与融合的内容 |

类比可以这样想：你去查资料，查询说明你在找什么，键帮助匹配资料，值是最后读到的内容。

**这个类比只帮助理解分工。**实际网络不会让你手工写一句“我要找杯子”，也不会手工把某个特征维度指定成“杯子信息”。查询、键、值都是数值向量，通常通过学习到的线性变换得到。

如果输入特征矩阵叫 `X`，可以写成：

```text
Q = X @ W_Q
K = X @ W_K
V = X @ W_V
```

`W_Q`、`W_K`、`W_V` 是三个可学习的权重矩阵。真实实现还可能包含偏置。训练会更新这些参数，逐渐学会如何匹配和融合信息。

#### 自注意力不等于 Q、K、V 的数值相同

“自注意力”说明查询、键和值来自**同一组输入**。但它们通常经过不同投影，因此数值可以不同：

```text
同一个 X
  ├─ 乘 W_Q → Q
  ├─ 乘 W_K → K
  └─ 乘 W_V → V
```

有些论文写“把同一个输入送给 Q、K、V”，说的是传入注意力模块的来源相同；模块内部仍可进行不同的学习投影。[PyTorch 多头注意力说明](https://docs.pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html)

### 四、一步一步手算一次注意力

先只用一个查询、两个候选信息，每个向量两个数：

```text
Q = [[1, 0]]

K = [[1, 0],
     [0, 1]]

V = [[10,  0],
     [ 0, 20]]
```

这三组数是专门设计的教学数据，没有直接代表真实物体的某种语义。我们暂时省略学习投影，只观察注意力内部怎样算。

#### 第一步：通过点积算匹配得分

对查询 `[1, 0]`：

```text
和第一个键匹配：1×1 + 0×0 = 1
和第二个键匹配：1×0 + 0×1 = 0
```

因此得分是：

```text
[[1, 0]]
```

代码：

```python
raw_scores = Q @ K.T
```

`K.T` 表示把二维矩阵的行和列交换。为什么要转置？

```text
Q 的形状： [1, 2]
K 的形状： [2, 2]
K.T 形状： [2, 2]

Q @ K.T： [1, 2] @ [2, 2] → [1, 2]
```

一般情况更容易看出作用：

```text
Q：[查询数量, 特征维度]
K：[候选数量, 特征维度]
K.T：[特征维度, 候选数量]

Q @ K.T → [查询数量, 候选数量]
```

结果的第 i 行、第 j 列，就是“第 i 个查询与第 j 个键”的匹配得分。

**点积得到的是匹配得分，不一定在 0～1 之间，也不一定非负。**它还不是权重。只有对向量另外归一化后，点积才可与余弦相似度直接联系；这里没有做那个步骤。

#### 第二步：除以特征维度的平方根

单头缩放点积注意力用：

```text
scores = (Q @ K.T) / √d
```

`d` 是查询和键的最后一维大小。这次 `d=2`，所以：

```text
√2 ≈ 1.4142
scores ≈ [[0.7071, 0]]
```

代码：

```python
scores = (Q @ K.T) / math.sqrt(Q.shape[-1])
```

缩放可以减轻维度变大时点积数值变大、软最大值过度偏向某个候选的问题。现在先记住“除以查询/键的维度平方根”，不要误以为除以物体数量。

#### 第三步：用软最大值把得分变成权重

对一行得分 `[s₁, s₂]`：

```text
权重₁ = exp(s₁) / [exp(s₁) + exp(s₂)]
权重₂ = exp(s₂) / [exp(s₁) + exp(s₂)]
```

`exp(s)` 表示指数函数 e 的 s 次方。

代入：

```text
exp(0.7071) ≈ 2.0281
exp(0)      = 1

权重₁ ≈ 2.0281 / 3.0281 ≈ 0.6698
权重₂ ≈ 1      / 3.0281 ≈ 0.3302
```

代码：

```python
weights = torch.softmax(scores, dim=-1)
```

`dim=-1` 表示沿最后一维计算。这里就是**对每个查询那一行的所有候选信息**计算软最大值。

每一行权重的总和为 1：

```text
0.6698 + 0.3302 = 1
```

注意：第二个原始得分是 0，**不代表第二个权重是 0**。指数函数满足 `exp(0)=1`，所以它仍然分到一部分权重。

#### 第四步：按权重融合值

```text
输出 = 权重₁ × 第一个值 + 权重₂ × 第二个值
     ≈ 0.6698 × [10, 0] + 0.3302 × [0, 20]
     ≈ [6.6976, 6.6048]
```

代码：

```python
output = weights @ V
```

输出是**新的特征表示**，不是“拿着”或者“看着”这些关系类别。后面还需要分类层把特征转换成关系得分。

完整计算可以写成：

```text
Attention(Q, K, V) = softmax(Q @ K.T / √d) @ V
```

配套示例省略了随机丢弃、注意力掩码等额外操作，展示的是最基础计算。[PyTorch 缩放点积注意力说明](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html)

### 五、每一步的形状为什么对得上

用一般形状表示：

| 张量 | 形状 | 含义 |
| --- | --- | --- |
| Q | `[查询数量, 查询维度]` | 谁在查询 |
| K | `[候选数量, 查询维度]` | 有哪些可匹配的信息 |
| V | `[候选数量, 值维度]` | 每份信息携带什么内容 |
| scores | `[查询数量, 候选数量]` | 每个查询对每份候选的得分 |
| weights | `[查询数量, 候选数量]` | 每个查询对每份候选的权重 |
| output | `[查询数量, 值维度]` | 每个查询得到的融合结果 |

需要满足：

1. Q 和 K 的最后一维一样，才能点积。
2. K 和 V 的候选数量一样，权重才能对应到每一份值。
3. V 的值维度不要求一定等于 Q 的查询维度。

假设五个物体各有八维查询/键特征，值也有八维：

```text
Q：[5, 8]
K：[5, 8]
V：[5, 8]
scores：[5, 5]
weights：[5, 5]
output：[5, 8]
```

权重矩阵中的一行表示一个物体怎样融合五个物体的信息；其中也可以包含自身的信息。是否屏蔽自身或某些位置，要看具体模型的注意力掩码。

### 六、三个容易混淆的“权重”和“掩码”

#### 1. 模型权重与注意力权重不同

| 名称 | 例子 | 从哪里来 |
| --- | --- | --- |
| 模型参数/权重 | `W_Q`、`W_K`、分类层权重 | 通过优化器训练更新，通常存入模型文件 |
| 注意力权重 | `[0.6698, 0.3302]` | 根据当前输入和模型参数，每次前向计算得到 |

输入换了，注意力权重也可以改变；可学习参数是在训练时更新的。

#### 2. 注意力权重不等于真实关系标签

“一个物体对另一个物体的注意力权重很大”，不能直接解释成“它一定拿着另一个物体”。

注意力是在融合特征。真实关系标签来自数据集标注；模型的关系预测需要经过关系分类器。权重可以提示信息来源，但不是正确性的证明。

#### 3. 注意力掩码与损失掩码作用不同

| 掩码 | 使用位置 | 控制什么 |
| --- | --- | --- |
| 注意力掩码 | 注意力得分/权重计算 | 哪些位置的信息可以参与融合 |
| 损失掩码 | 损失计算 | 哪些监督项参与当前训练 |

ImparTail 重点讨论的是关系监督的**损失掩码**。不要因为它也叫“掩码”，就和限制注意力访问的位置混为一谈。

### 七、多头、空间注意力和时间注意力

#### 多头注意力

一个注意力头进行一组查询、键、值的计算。多头注意力使用多组投影，分别计算，再拼接结果、继续进行输出投影。

可以理解成“从多个学到的表示空间同时融合信息”，但不能保证“第一头一定看颜色，第二头一定看位置”。它们的分工是训练学出来的，不是手工固定的。[PyTorch 多头注意力说明](https://docs.pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html)

#### 空间注意力

在同一帧内融合不同物体或物体对的信息：

```text
同一帧中的关系特征
  → 相互提供上下文
  → 更新关系特征
```

这里的“空间”强调同一帧的场景上下文，不表示简单地拿两个框的距离当注意力权重。

#### 时间注意力

在不同帧之间融合信息：

```text
第 1 帧特征、第 2 帧特征、第 3 帧特征
  → 结合顺序与跨帧上下文
  → 更新特征
```

视频顺序很重要。标准注意力仅凭向量本身和集合式计算，不会自动知道谁是“前一帧”；模型通常通过时间位置表示等设计提供顺序线索。

输入包含多少帧、怎样组建跨帧候选、是否只能使用过去帧，都需要看具体模型。**使用时间注意力，并不自动等于预测未来。**

### 八、什么是场景图

场景图用“物体＋关系”描述场景：

```text
人 ──拿着──> 杯子
人 ──看着──> 杯子
```

- **节点**：具体物体实例，如画面中的这个人、这个杯子。
- **边**：物体之间的关系。
- **关系三元组**：`(主体, 关系, 客体)`。

这里“主体、客体”表示一条有方向关系的两端，不是在背语言学句法。

例如：

```python
relationship = ("人", "拿着", "杯子")
```

注意三个细节：

1. “人—拿着—杯子”和“杯子—拿着—人”不同，不能随便交换顺序。
2. 同一个物体对可能同时有多个关系，如“看着”和“拿着”。
3. 如果出现两个杯子，它们是两个物体实例；即便类别相同，也应有不同框和实例编号。

“哪些关系可以标注”“方向怎样规定”“一个物体对允许哪些组的关系”，都由具体数据集定义。

Action Genome 的关系包含注意关系、空间关系、接触关系等组。空间关系的方向可能按其标注约定排列，不能把你自己写的中文三元组直接当成项目内的索引顺序；应核对数据加载和评估代码。[STTran 官方评估代码](https://github.com/yrcong/STTran/blob/main/lib/evaluation_recall.py)

### 九、静态、动态图生成与未来预测

| 任务 | 输入 | 输出 |
| --- | --- | --- |
| 静态场景图生成 | 单张图片 | 这张图片的物体与关系 |
| 视频场景图生成 | 已观察到的视频帧 | 这些帧各自的场景图 |
| 场景图未来预测 | 已观察到的前面一段视频 | 后续尚未观察到的帧的场景图 |

“动态”不是简单地把一个关系写成动词。输入是否包含视频时序信息，才是这里区分静态和动态的主要依据。

例如：

```text
第 1 帧：人—看着—杯子
第 2 帧：人—拿着—杯子
第 3 帧：人—喝着—杯子
```

用这三帧识别它们各自的关系，是视频场景图生成；只观察前两帧，预测第三帧的关系，是未来预测。这个例子仅用日常词汇解释任务，真实关系名称以数据集类别表为准。

### 十、STTran 的流程怎样接上这些基础

STTran 的主要流程可以先这样看：

```text
视频帧
  ↓
预训练检测器：物体位置、类别信息、视觉特征
  ↓
组合人和物体的关系表示
  ↓
空间编码器：结合一帧内的上下文
  ↓
时间解码器：结合相邻帧的时序上下文
  ↓
关系分类层
  ↓
关系得分 → 场景图
```

STTran 的关系表示结合主体/客体视觉特征、联合区域与空间信息、类别相关信息。先理解各阶段的输入输出，之后再读具体维度和模块。[STTran 论文页面](https://openaccess.thecvf.com/content/ICCV2021/html/Cong_Spatial-Temporal_Transformer_for_Dynamic_Scene_Graph_Generation_ICCV_2021_paper.html)

本教材中的“两维向量注意力”只帮助你理解基础运算，并没有实现检测器、关系特征构造、完整 Transformer 或真实场景图评估。

### 十一、三个任务设置要分清

| 设置 | 已提供的信息 | 模型主要还要预测什么 |
| --- | --- | --- |
| PredCls：关系分类 | 图片/视频帧、真实物体框、真实物体类别 | 关系 |
| SGCls：场景图分类 | 图片/视频帧、真实物体框 | 物体类别和关系 |
| SGDet：场景图检测 | 图片/视频帧 | 物体框、物体类别和关系 |

PredCls 不是“输入几个类别名字就预测关系”。模型仍然可以利用图片特征，只是位置和物体类别已经给定。

SGDet 中，如果检测器漏掉杯子，关系模块就很难生成与这个杯子相关的正确三元组。因此 SGDet 结果包含检测误差，更接近完整的视觉任务。

**比较论文结果时，要先确认属于同一个设置。**PredCls 的分数不能直接与 SGDet 的分数比较。[ImparTail 任务定义](https://arxiv.org/html/2411.13059v2#S11.SS1)

### 十二、R@K 与 mR@K 为什么都要看

#### R@K：前 K 个关系预测找回多少真实关系

先按照项目规定计算关系三元组的得分，排序，取前 K 个，再与真实标注匹配。

对于单个评估帧，可以理解为：

```text
R@K = 前 K 个预测匹配到的真实关系数量 / 真实关系总数量
```

例如某帧有六条真实关系，前十个预测匹配到四条：

```text
R@10 = 4/6 ≈ 66.7%
```

**分母是六条真实关系，不是十个预测。**后者是在考虑精确率，而这里讨论召回率。

完整评估还需要检查物体类别、关系类别、物体框的匹配条件；例如检测任务会检查框是否满足交并比阈值。不要只判断三元组的文字一样。

STTran 的实现先计算各帧召回率，再取平均，因此不能简单拿整套数据的总匹配数除以总真实数，冒充它的官方 R@K。[STTran 官方评估代码](https://github.com/yrcong/STTran/blob/main/lib/evaluation_recall.py)

#### mR@K：先看每个关系类别，再平均

直观理解：

```text
先计算每个关系类别的召回表现
      ↓
各个关系类别等权平均
```

简化写法：

```text
mR@K = (类别 1 的召回率 + 类别 2 的召回率 + ...)/类别数量
```

不要把“平均召回率”误解成“R@10、R@20、R@50 的平均”。它主要是在**关系类别维度**做平均。

#### 用一个教学例子理解长尾问题

假设在一个简化统计例子里：

| 类别 | 真实数量 | 找回数量 | 该类召回率 |
| --- | ---: | ---: | ---: |
| 常见关系 | 90 | 72 | 80% |
| 少见关系 | 10 | 1 | 10% |

把所有实例直接汇总，召回率是 `73/100=73%`。两类等权平均，则是 `(80%+10%)/2=45%`。

这个例子只是展示**按实例统计和按类别平均**的差别；它没有实现官方的逐帧聚合、top-K 排序和匹配协议。

普通召回更容易体现常见关系的成绩；类别平均让少见关系也占一份。少见关系改善后，mR 可能上升，但普通 R 不一定同时上升。这正是阅读去偏论文时需要检查的取舍。

真实复现必须使用官方评估器处理类别缺失、帧平均、方向、约束和 top-K 等细节。[ImparTail 指标与实验说明](https://arxiv.org/html/2411.13059v2#S5)

### 十三、关系约束又是一个单独设置

ImparTail 在 Action Genome 中使用以下构图设置：

| 设置 | 入门理解 |
| --- | --- |
| With Constraint：有约束 | 对一个物体对，在每个关系类别组中选择一个预测 |
| No Constraint：无约束 | 可从同一物体对保留多个候选关系，再按协议排序评估 |
| Semi Constraint：半约束 | 对允许多标签的关系组，按阈值选择候选；单标签组仍按对应规则处理 |

Action Genome 有不同关系类别组，因此 **With Constraint 不应被解释成‘同一个物体对，所有组加起来永远只有一条关系’**。Semi Constraint 的注意关系与空间/接触关系也不是完全相同的处理。

这些是论文对应数据集的评估协议，不是所有场景图论文通用的一条规则。比较结果时，要让任务模式、关系约束、K 值、数据划分和匹配规则一致。[ImparTail 构图策略](https://arxiv.org/html/2411.13059v2#S3)及[STTran 官方实现](https://github.com/yrcong/STTran/blob/main/lib/evaluation_recall.py)

### 十四、ImparTail 具体接在哪一步

先把普通训练连起来：

```text
视频 → 特征 → 空间/时间上下文 → 关系预测
                                   ↓
真实关系标注 → 关系损失 → 反向传播 → 更新参数
```

ImparTail 复用已有视频场景图模型的主要结构，重点改变关系监督的参与方式，以减少高频关系的主导作用：

```text
关系预测 + 真实标注
      ↓
各项关系损失
      ↓
按规则生成掩码
      ↓
被保留的损失参与反向传播
```

这是训练策略的修改，不要求大语言模型。论文还研究未来预测和鲁棒性；读基础时先聚焦“STTran＋视频场景图生成”的一条路径。[ImparTail 论文页面](https://openaccess.thecvf.com/content/CVPR2025/html/Peddi_Towards_Unbiased_and_Robust_Spatio-Temporal_Scene_Graph_Generation_and_Anticipation_CVPR_2025_paper.html)

#### 掩码损失的最小数学形式

```text
屏蔽后的某项损失 = (1 - m) × 原来的该项损失
```

在论文这个符号约定中：

- `m=0`：保留，因为 `1-m=1`。
- `m=1`：屏蔽，因为 `1-m=0`。

例如原来的三项损失是 `[2, 3, 4]`，掩码是 `[0, 1, 0]`：

```text
保留系数： [1, 0, 1]
屏蔽后：   [2, 0, 4]
求和：     6
```

这里只说明作用位置。论文完整的掩码生成、随机性、课程安排和不同基线损失，后续要结合算法和源码读，不能把这三个数字的例子当作完整 ImparTail。[ImparTail 掩码损失](https://arxiv.org/html/2411.13059v2#S4.SS2)

#### 屏蔽一个损失，不等于共享参数全部停止更新

假设三项损失都依赖同一个参数 `w`：

```text
总损失 = L₁(w) + 0×L₂(w) + L₃(w)
```

则：

```text
总损失对 w 的梯度 = L₁ 的梯度 + L₃ 的梯度
```

第二项没有贡献，但第一、三项仍然可以更新同一个参数。

如果你把三项损失本身作为三个独立的叶张量，确实可以看到它们的梯度是 `[1, 0, 1]`。但这不等于真实分类器的中间得分、全部参数都只按这个向量更新：分类损失本身还可能耦合多个得分，网络参数也会共享。读掩码时要明确“屏蔽的对象到底是哪一项”。

### 五、综合程序到底在做什么

配套程序将这些概念接起来：

```text
人工创建的图片张量 [100,100,3]
    ↓ 类型转换、范围缩放、维度调整、增加批次维度
模型常用输入形状 [1,3,100,100]

人工给定两个物体框 → 计算交并比

人工给定物体特征 [2,3]
    ↓ 将两行特征拼接
一个物体对的特征 [1,6]
    ↓ 小线性层
三个关系原始得分 [1,3]
    ↓ 和标签比较，保留逐项损失
逐项损失 [1,3]
    ↓ 屏蔽第二项，汇总为一个数
有效损失 []
    ↓ 求导，再更新参数
关系分类层的参数改变
```

其中 `[]` 表示标量张量，没有额外维度，仍然是张量。

图像、框和特征都是人工编写的教学数据。程序没有从全黑图片识别物体，也没有用真实视频提取特征。它的用途是检查这些接口和数学怎样衔接，只有最后的小关系分类层参与一次训练。

这里最后一层的三个输出对应不同的权重行，所以被屏蔽输出的那一行梯度为零；如果之前还有共享特征提取网络，保留的关系损失仍可更新它的参数。

再做三次修改，每次只改一个设置：

1. 改成全保留掩码 `[0,0,0]`，检查第二个权重行的梯度是否还为零。
2. 改成全屏蔽掩码 `[1,1,1]`，检查本例普通 SGD 下损失、梯度和参数是否变化。此例没有动量或权重衰减，不能把观察结果推广到所有优化器设置。
3. 把物体特征变成每个四维，先修改拼接与线性层的输入特征数，再运行核对形状。

最终作业：新建自己的脚本，使用三件物体，选择两个不同的物体对，分别拼接特征；让关系模型同时处理这两对，打印输入、预测、目标和掩码的形状，并解释你汇总损失的分母。

这份表用于读详细教材时快速查找，先理解例子，再回来记住符号和代码的对应关系。

### 一、视觉和形状

| 术语或符号 | 中文含义 | 读代码时看哪里 |

注意：二维坐标的 x 对应水平方向，y 对应垂直方向；HWC 数组中的行索引对应 y，列索引对应 x。

### 二、训练和数学

| 术语或写法 | 中文含义 | 容易混淆的地方 |
| --- | --- | --- |
| 标量 | 单个数 | 张量形状可以是 `[]` |
| 向量 | 一串数 | 特征维度不等于类别数量 |
| 矩阵 | 二维数字排列 | 行列的含义由任务定义 |
| `*` | 逐元素乘法 | 与矩阵乘法 `@` 不同 |
| `@` | 矩阵乘法 | 要满足中间维度匹配 |
| `** 2` | 平方 | 不表示矩阵乘法或转置 |
| 参数 | 训练时更新的数字 | 与输入数据、标注不同 |
| 偏置 | 线性计算后加的参数 | 与论文中的类别偏差不是同一个概念 |
| 原始得分 | 模型未经概率转换的输出 | 可以为负，通常不是概率 |
| 概率 | 对结果可能性的数值表示 | 要看任务采用哪种概率转换 |
| 标签 | 已知目标答案 | 多类别编号和多标签零一向量不同 |

| 梯度 | 各变量偏导数组成的集合 | 共享参数的梯度可能来自多项损失 |
| `backward()` | 反向传播并保存梯度 | 不自动执行参数更新 |
| `no_grad()` | 暂停记录块内的求导运算 | 不清除已有梯度 |
| `zero_grad()` | 清除旧梯度 | 不将模型参数清零 |
| `step()` | 优化器更新参数 | 要先有本轮梯度 |
| 学习率 η | 参数更新的步长系数 | 增大它不保证学习更快 |
| 掩码 | 控制某些项是否参与计算 | 一和零的含义要看约定 |

### 三、常用公式

#### 1. 像素范围缩放

对常见八位 RGB 图片：

\[
p_{缩放}=p_{原始}/255
\]

范围从零到 255 转到零到一。需要先转为浮点数据。

按指定均值和标准差进行标准化时：

\[
p_{标准化}=(p_{缩放}-\mu)/\sigma
\]

标准差必须大于零；均值和标准差的选择应与模型的输入约定对应。

#### 2. 边界框

对于连续坐标的框 \([x_1,y_1,x_2,y_2]\)，且右下角不小于左上角：

\[
宽=x_2-x_1,\quad 高=y_2-y_1
\]

\[
中心_x=(x_1+x_2)/2,\quad 中心_y=(y_1+y_2)/2
\]

\[
交并比=\frac{交集面积}{A面积+B面积-交集面积}
\]

使用此式时，并集面积必须大于零；本练习使用正面积框。

数据集的框格式必须先核对；本教材不使用“包含两端像素所以加一”的另一套离散坐标约定。

#### 3. 点积与长度

\[
u\cdot v=\sum_i u_i v_i
\]

\[
\|u\|_2=\sqrt{\sum_i u_i^2}
\]

点积是一个数字，向量长度也是一个数字；它们用途不同。

#### 4. PyTorch 线性层

\[
Y=XW^T+b
\]

X 的形状为 `[N, 输入特征数]`；这里 W 专指 `nn.Linear` 存储的权重，形状为 `[输出特征数, 输入特征数]`；Y 的形状为 `[N, 输出特征数]`。

有些教材写 `Y=XW+b`，对应的是把 W 定义为 `[输入特征数, 输出特征数]`，两种写法的矩阵定义不同。

#### 5. 均方误差

\[
L=\frac1M\sum_{i=1}^{M}(\hat y_i-y_i)^2
\]

M 是参与平均的元素数量，默认的 `MSELoss` 对所有误差元素取平均。

#### 6. 链式法则与参数更新

对于 \(\hat y=wx\)、\(L=(wx-t)^2\)：

\[
\frac{\partial L}{\partial w}=2(wx-t)x
\]

最简单、没有动量和权重衰减的梯度下降更新：

\[
w_{新}=w_{旧}-\eta\frac{\partial L}{\partial w}
\]

梯度为负时，减去负数会使参数增大。下降指损失的目标方向，不要求每个参数的数值都下降。

#### 7. 概率转换与分类损失

独立二元判断使用 sigmoid：

\[
\sigma(s)=\frac1{1+e^{-s}}
\]

从一组类别中选一个，常用 softmax：

\[
p_i=\frac{e^{s_i}}{\sum_j e^{s_j}}
\]

真实类别为 c 时，交叉熵可理解为：

\[
L=-\ln p_c
\]

对于目标 \(y\in\{0,1\}\) 的二元判断，理论上的二元交叉熵为：

\[
L=-y\ln p-(1-y)\ln(1-p)
\]

这里的数学式使用概率帮助理解；PyTorch 的 `CrossEntropyLoss` 和 `BCEWithLogitsLoss` 接收原始得分，在内部进行相应的稳定计算。

#### 8. 单头注意力

\[
A=softmax\left(\frac{QK^T}{\sqrt{d_k}}\right),\quad 输出=AV
\]

在教材的二维例子中，Q 是 `[查询数,d_k]`，K 是 `[键数,d_k]`，V 是 `[键数,值特征数]`；A 为 `[查询数,键数]`，对每个查询的所有键做 softmax。

注意力是信息组合机制，权重不直接等于场景图关系标签。

#### 9. 教学示例中的掩码平均损失

\[
L_{掩码}=\frac{\sum_i(1-m_i)\ell_i}{\sum_i(1-m_i)}
\]

本例约定 \(m_i=1\) 表示屏蔽；至少有一项被保留时使用上式。配套代码对全屏蔽情况保护分母。

这是练习中“只平均保留项”的约定；实际论文的汇总方式还要对照其基线损失和实现，不能仅凭这条式子认定完整算法相同。

"""视觉基础练习：图片张量、维度、预处理、物体框和特征。

所有数字都是手工构造的教学数据，没有调用真实物体检测模型。
只依赖已安装的 torch，不下载图片或权重，在 CPU 上即可运行。
"""

import torch


def single_box_iou(box_a, box_b):
    """计算两个正面积 xyxy 框的交并比，返回单元素张量。

    本函数采用连续边界坐标，宽高不加 1。
    """
    if box_a.shape != (4,) or box_b.shape != (4,):
        raise ValueError("每个框必须是一维张量，并且恰好有四个数字。")
    # 切片的前两个元素是左上边界，后两个是右下边界。
    size_a = box_a[2:] - box_a[:2]
    size_b = box_b[2:] - box_b[:2]
    if not bool((size_a > 0).all()) or not bool((size_b > 0).all()):
        raise ValueError("物体框必须有正的宽度和高度。")

    # 重合区域取更靠右、更靠下的左上边界。
    intersection_left_top = torch.maximum(box_a[:2], box_b[:2])
    # 重合区域取更靠左、更靠上的右下边界。
    intersection_right_bottom = torch.minimum(box_a[2:], box_b[2:])
    # 分离时边界差值可能为负，将其改成 0，表示没有面积交集。
    intersection_size = (intersection_right_bottom - intersection_left_top).clamp(min=0)
    intersection_area = intersection_size.prod()  # 交集宽乘以交集高。

    area_a = size_a.prod()
    area_b = size_b.prod()
    union_area = area_a + area_b - intersection_area
    return intersection_area / union_area


def xyxy_to_cxcywh(box):
    """将合法的 xyxy 框转换成中心横坐标、中心纵坐标、宽、高。"""
    center = (box[:2] + box[2:]) / 2
    size = box[2:] - box[:2]
    return torch.cat([center, size])


def main():
    torch.set_printoptions(precision=3, sci_mode=False)

    print("一、创建两行两列的 RGB 图片")
    print("颜色排列：第一行红、绿；第二行蓝、白。")
    image_hwc = torch.tensor([
        [[255, 0, 0], [0, 255, 0]],
        [[0, 0, 255], [255, 255, 255]]
    ], dtype=torch.uint8)
    print("原始图片张量：\n", image_hwc)
    print("高度、宽度、通道形状：", list(image_hwc.shape))
    print("数据类型：", image_hwc.dtype)
    print("第一行第二列的绿色像素：", image_hwc[0, 1].tolist())
    print("全部红色分量：\n", image_hwc[:, :, 0])

    print("\n二、改变维度顺序，并加入批次维度")
    image_chw = image_hwc.permute(2, 0, 1)
    print("通道、高度、宽度形状：", list(image_chw.shape))
    print("CHW 顺序下读取同一个绿色像素：", image_chw[:, 0, 1].tolist())
    # 在最前面插入一个长度为 1 的维度，不会增加新像素。
    image_nchw = image_chw.unsqueeze(0)
    print("批次、通道、高度、宽度形状：", list(image_nchw.shape))
    repeated_batch = torch.stack([image_chw, image_chw], dim=0)
    print("重复两张教学图片组成批次：", list(repeated_batch.shape))

    print("\n三、类型转换、归一化和教学标准化")
    image_float = image_chw.float()
    print("仅转浮点数后的绿色像素：", image_float[:, 0, 1].tolist())
    print("转为浮点数后的类型：", image_float.dtype)
    image_01 = image_float / 255.0
    print("除以 255 后的绿色像素：", image_01[:, 0, 1].tolist())
    print("缩放后的最小值、最大值：", image_01.min().item(), image_01.max().item())
    # 以下均值和标准差仅为手算演示，不是任何预训练模型的通用配置。
    mean = torch.tensor([0.5, 0.5, 0.5]).reshape(3, 1, 1)
    std = torch.tensor([0.5, 0.5, 0.5]).reshape(3, 1, 1)
    image_standardized = (image_01 - mean) / std
    print("教学标准化后的绿色像素：", image_standardized[:, 0, 1].tolist())

    print("\n四、图像坐标和张量索引")
    horizontal = 1  # 横坐标，也就是列位置。
    vertical = 0  # 纵坐标，也就是行位置。
    print("图像坐标 (1, 0) 对应 HWC[0, 1]：", image_hwc[vertical, horizontal].tolist())

    print("\n五、物体框格式与交并比")
    box_a = torch.tensor([10., 10., 50., 50.])
    box_b = torch.tensor([30., 30., 70., 70.])
    print("框 A，xyxy：", box_a.tolist())
    print("框 B，xyxy：", box_b.tolist())
    print("框 A，中心横坐标、中心纵坐标、宽、高：", xyxy_to_cxcywh(box_a).tolist())
    print("框 A 面积：", (box_a[2:] - box_a[:2]).prod().item())
    print("框 B 面积：", (box_b[2:] - box_b[:2]).prod().item())
    intersection_size = (
        torch.minimum(box_a[2:], box_b[2:])
        - torch.maximum(box_a[:2], box_b[:2])

    print("交集宽、高：", intersection_size.tolist())
    print("交集面积：", intersection_size.prod().item())

    separated_box = torch.tensor([80., 80., 100., 100.])

    print("\n六、局部区域与卷积核的教学计算")

    print("局部区域：\n", patch)
    print("人为指定的卷积核：\n", kernel)
    print("对应元素相乘：\n", patch * kernel)

    print("\n七、用张量形状表示物体特征")
    # 每行一个物体，每列一个特征分量；这些不是模型提取的真实特征。

        [0.7, 0.3, -0.2, 0.5]   # 示意“杯子”的四维特征。
    ])
    print("两个物体，每个物体四个特征数：", list(object_features.shape))
    pair_feature = torch.cat([object_features[0], object_features[1]])
    print("拼接人的特征和杯子的特征：", pair_feature)
    print("拼接后特征长度：", pair_feature.numel())
    print("这些特征只演示数字排列，没有完成真实检测或关系预测。")

    print("\n独立练习：")
    print("1. 将四个像素改成黑、白、绿、红，预测三个颜色通道。")
    print("2. 在自己的文件中写出 HWC → CHW → 浮点数/255 → NCHW。")

def demonstrate_matrix_operations():
    print_heading("三、矩阵乘法与线性层")
    inputs = torch.tensor([[1., 2., 3.], [4., 5., 6.]])

    print("数学写法的权重 W：\n", weights)

        linear_layer.weight.copy_(weights.T)
        linear_layer.bias.copy_(b)
    print("PyTorch 线性层实际权重形状：", list(linear_layer.weight.shape))
    print("线性层输出：\n", linear_layer(inputs).detach())
    print("与手算矩阵公式相同：", torch.allclose(linear_layer(inputs), inputs @ weights + b))
    print("练习：把数学写法 W 的第一列改成 [1,1,1]，第一列输出怎样变化？")


def demonstrate_broadcasting():
    print_heading("四、广播既方便，也可能掩盖形状错误")
    predictions = torch.tensor([[1.], [2.], [3.], [4.]])
    original_targets = torch.tensor([1., 2., 3., 4.])
    incorrect_difference = predictions - original_targets
    print("预测形状：", list(predictions.shape))
    print("未调整的目标形状：", list(original_targets.shape))
    print("直接相减后的形状：", list(incorrect_difference.shape))
    print("直接相减：\n", incorrect_difference)
    print("错误的平均平方损失：", (incorrect_difference ** 2).mean().item())
    correct_targets = original_targets.unsqueeze(1)
    print("修正后的目标形状：", list(correct_targets.shape))
    print("正确的平均平方损失：", F.mse_loss(predictions, correct_targets).item())
    print("练习：用 [6,1] 和 [6] 的例子检查结果形状，不要只看元素数。")


def demonstrate_statistics():
    print_heading("五、均值、总体方差与标准差")
    values = torch.tensor([1., 2., 3.])
    mean = values.mean()
    variance = ((values - mean) ** 2).mean()
    std = variance.sqrt()
    standardized_values = (values - mean) / std
    print("数值：", values)
    print("均值：", mean.item())
    print("与均值的差：", values - mean)
    print(f"总体方差（分母是元素数）：{variance.item():.4f}")
    print(f"标准差：{std.item():.4f}")
    print("标准化结果：", standardized_values)
    print("标准化后均值：", standardized_values.mean().item())
    print("说明：这里用显式公式计算总体方差，避免不同方差校正约定的混淆。")


def demonstrate_autograd():
    print_heading("六、链式法则、梯度与一步更新")
    x = torch.tensor(2.0)
    targets = torch.tensor(6.0)

    # 从相同初始值分别做一次更新，不要把两个实验的梯度混在一起。
    for learning_rate in [0.1, 0.5]:
        w = torch.tensor(1.0, requires_grad=True)
        predictions = w * x
        loss = (predictions - targets) ** 2
        manual_gradient = 2 * (predictions.detach() - targets) * x
        print(f"\n学习率 {learning_rate}，初始参数 {w.item()}")
        print("初始预测、初始损失：", predictions.item(), loss.item())
        print("反向传播之前的梯度：", w.grad)
        loss.backward()
        print("手算公式 2×(预测-目标)×输入：", manual_gradient.item())
        print("自动求导保存的梯度：", w.grad.item())

        with torch.no_grad():
            w -= learning_rate * w.grad
            updated_predictions = w * x
            updated_loss = (updated_predictions - targets) ** 2
        print(f"更新后的参数：{w.item():.4f}，预测：{updated_predictions.item():.4f}，损失：{updated_loss.item():.4f}")
        w.grad.zero_()
        print(f"清零后的梯度：{w.grad.item():.4f}；参数仍是：{w.item():.4f}")

    print("\n练习：把初始 w 改成 4、学习率设为 0.1，先手算再运行。")


def demonstrate_loss_gradients():
    print_heading("七、多个参数的梯度与平均平方损失")
    parameters = torch.tensor([2., 3.], requires_grad=True)
    total_loss = (parameters ** 2).sum()
    total_loss.backward()
    print("参数：[2,3]；平方和损失：", total_loss.item())
    print("每个参数自己的梯度：", parameters.grad)

    predictions = torch.tensor([2., 4.], requires_grad=True)
    targets = torch.tensor([1., 6.])
    mean_loss = F.mse_loss(predictions, targets)
    mean_loss.backward()
    print("\n预测：", predictions.detach(), "；目标：", targets)
    print("平均平方损失：", mean_loss.item())
    print("损失对预测值的梯度：", predictions.grad)
    print("公式：2×(预测-目标)÷元素数")
    print("练习：对新张量使用 reduction='sum'，观察损失及梯度放大多少。")


def demonstrate_classification_losses():
    print_heading("八、原始分数、概率与分类损失")
    logits = torch.tensor([[2., 1., 0.]], requires_grad=True)

    print(f"交叉熵（损失直接接收原始分数）：{cross_entropy.item():.4f}")
    print(f"手算 -ln(正确类别概率)：{-probabilities[0, 0].log().item():.4f}")
    print("原始分数的梯度：", logits.grad)

    binary_logits = torch.tensor([0.0], requires_grad=True)

    print("原始分数的梯度：", binary_logits.grad)

"""第三步的注意力练习：用小矩阵理解匹配、权重和信息融合。

全部在处理器上运行；不下载数据、图片或模型。
这些向量是教学数字，不代表真实物体的语义特征。
"""

import math

import torch


def compute_attention(queries, keys, values):
    """计算最基础的单头注意力，不含额外掩码和随机丢弃。"""
    # 查询形状：[查询数量, 特征维度]
    # 键形状：  [候选数量, 特征维度]
    # 值形状：  [候选数量, 值维度]
    raw_scores = queries @ keys.T
    feature_dim = queries.shape[-1]
    scaled_scores = raw_scores / math.sqrt(feature_dim)
    attention_weights = torch.softmax(scaled_scores, dim=-1)  # 每一行分别归一化。
    output = attention_weights @ values
    return raw_scores, scaled_scores, attention_weights, output


def show_attention_calculation(heading, queries, keys, values):
    print("\n" + heading)
    print("查询：", queries)
    print("键：", keys)
    print("值：", values)
    print("查询、键、值的形状：", list(queries.shape), list(keys.shape), list(values.shape))

    raw_scores, scaled_scores, attention_weights, output = compute_attention(queries, keys, values)
    print("第一步，查询与键做点积：", raw_scores)
    print("第二步，除以特征维度的平方根：", scaled_scores)
    print("第三步，转换成注意力权重：", attention_weights)
    print("各行权重之和：", attention_weights.sum(dim=-1))
    print("第四步，用权重融合值：", output)
    print("输出形状：", list(output.shape))
    return attention_weights, output


def main():
    torch.set_printoptions(precision=4, sci_mode=False)

    # float32 是浮点类型；device="cpu" 明确在处理器上计算。
    queries = torch.tensor([[1., 0.]], dtype=torch.float32, device="cpu")
    keys = torch.tensor([[1., 0.], [0., 1.]], dtype=torch.float32, device="cpu")
    values = torch.tensor([[10., 0.], [0., 20.]], dtype=torch.float32, device="cpu")

    initial_weights, initial_output = show_attention_calculation("一、一个查询，两份信息", queries, keys, values)
    print("手算核对：权重约 [0.6698, 0.3302]；输出约 [6.6976, 6.6048]。")

    second_query = torch.tensor([[0., 1.]], dtype=torch.float32)
    show_attention_calculation("二、改变查询，匹配方向也会变化", second_query, keys, values)

    equal_score_query = torch.tensor([[1., 1.]], dtype=torch.float32)
    show_attention_calculation("三、两个匹配得分相同，权重各为一半", equal_score_query, keys, values)

    changed_values = torch.tensor([[10., 0.], [0., 100.]], dtype=torch.float32)
    updated_weights, updated_output = show_attention_calculation("四、只改变值，观察权重与输出", queries, keys, changed_values)
    print("权重是否保持相同：", "是" if torch.allclose(initial_weights, updated_weights) else "否")
    print("原来输出：", initial_output)
    print("改变值后的输出：", updated_output)
    print("原因：匹配使用查询和键；融合内容来自值。")

    query_batch = torch.tensor([[1., 0.], [0., 1.]], dtype=torch.float32)
    show_attention_calculation("五、两个查询同时计算，每行得到自己的结果", query_batch, keys, values)

    print("\n六、自注意力的输入来源相同，学习投影可以不同")
    input_features = torch.tensor([[1., 0.], [0., 1.]], dtype=torch.float32)
    # 以下投影是教学固定数字；真实模型中它们是通过训练学习的参数。
    query_projection = torch.tensor([[1., 0.], [0., 1.]], dtype=torch.float32)
    key_projection = torch.tensor([[0., 1.], [1., 0.]], dtype=torch.float32)
    value_projection = torch.tensor([[10., 0.], [0., 20.]], dtype=torch.float32)
    projected_queries = input_features @ query_projection
    projected_keys = input_features @ key_projection
    projected_values = input_features @ value_projection
    show_attention_calculation("同一组输入经过三种投影", projected_queries, projected_keys, projected_values)
    print("来源相同，并不保证查询、键、值的数值相同。")

    print("\n理解检查")
    print("1. 如果查询改成 [0, 0]，两个权重和输出分别是多少？")
    print("2. 为什么原始得分为 0 的候选仍有非零权重？")
    print("3. 值有三个分量时，输出会有几个分量？")
    print("4. 注意力输出是融合特征，还需要分类层才能得到关系预测。")
    print("5. 本文件没有训练模型；也没有实现 STTran 或 ImparTail。")


if __name__ == "__main__":
    main()

"""综合练习：串起图片形状、给定物体框、示例特征、关系损失与一次更新。"""
import torch

torch.manual_seed(7)

# 为练习形状而创建的全黑图片；下面的框和特征都是人工指定。
# 本程序没有从图片检测物体，不代表训练好的视觉识别系统。
image_hwc = torch.zeros((100, 100, 3), dtype=torch.uint8)
image_nchw = (image_hwc.float() / 255).permute(2, 0, 1).unsqueeze(0)
print("一、图片形状：", list(image_hwc.shape), "→", list(image_nchw.shape))

boxes = torch.tensor([[10.0, 10.0, 50.0, 50.0], [30.0, 30.0, 70.0, 70.0]])
intersection_size = (torch.minimum(boxes[0, 2:], boxes[1, 2:])
                     - torch.maximum(boxes[0, :2], boxes[1, :2])).clamp(min=0)
intersection_area = intersection_size.prod()
areas = ((boxes[:, 2] - boxes[:, 0]) * (boxes[:, 3] - boxes[:, 1]))
iou = intersection_area / (areas.sum() - intersection_area)
print("二、给定框的交并比：", round(iou.item(), 6))

# 两个物体各有三个教学特征，拼接成这个物体对的六个特征。
object_features = torch.tensor([[1.0, 0.0, 1.0], [0.0, 1.0, 1.0]])
pair_features = torch.cat([object_features[0], object_features[1]]).unsqueeze(0)
print("三、物体特征形状：", list(object_features.shape))
print("物体对特征形状：", list(pair_features.shape))

# 三个独立关系是否成立，使用多标签二元损失。
model = torch.nn.Linear(6, 3)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
criterion = torch.nn.BCEWithLogitsLoss(reduction="none")
targets = torch.tensor([[1.0, 0.0, 1.0]])
mask = torch.tensor([[0.0, 1.0, 0.0]])  # 第二项屏蔽。
keep = 1 - mask

optimizer.zero_grad()
scores = model(pair_features)
individual_losses = criterion(scores, targets)
loss = (individual_losses * keep).sum() / keep.sum().clamp(min=1)
loss.backward()

print("四、关系原始得分形状：", list(scores.shape))
print("目标与掩码形状：", list(targets.shape), list(mask.shape))
print("逐项损失：", individual_losses.detach().tolist())
print("本次有效损失：", round(loss.item(), 6))
print("分类层权重梯度形状：", list(model.weight.grad.shape))
print("第二个输出对应的权重行梯度：", model.weight.grad[1].tolist())

optimizer.step()
with torch.no_grad():
    new_scores = model(pair_features)
    new_losses = criterion(new_scores, targets)
    new_loss = (new_losses * keep).sum() / keep.sum().clamp(min=1)

print("五、更新后的有效损失：", round(new_loss.item(), 6))
print("本例一次更新后损失是否降低：", new_loss.item() < loss.item())
print("说明：这里只训练一个小关系分类层，没有训练图像特征提取器。")
