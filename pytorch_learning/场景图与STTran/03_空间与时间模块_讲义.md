# 第三天：STTran 的空间与时间模块详解

这一课把“关系特征送进 Transformer”这句话拆开讲清楚。你需要同时看懂两件事：一行关系特征怎样与其他行交换信息，以及代码怎样把不同视频帧中的关系组织成张量。

读完后，你应当能独立说明：Q、K、V 从哪里来；注意力怎样计算；空间模块为什么补齐；时间模块怎样构造相邻帧窗口；一个关系在两个窗口出现时最终保留哪个结果；输出怎样恢复为关系特征的原始行顺序。

本课对应 [STTran 论文](https://arxiv.org/abs/2107.12309)的空间编码器和时间解码器。实现细节按[官方 lib/transformer.py](https://github.com/yrcong/STTran/blob/main/lib/transformer.py)核对。配套代码使用人工关系特征和较小的维度，不包含图片检测、类别预测和真实数据集训练。

## 一、先确认模型正在处理什么

### 1. 输入的一行是一个物体对的特征

假设第 0 帧中有一个人、一只杯子、一本书。你已经为两个物体对构造了特征：

```text
关系行 0：人 → 杯子 的关系特征
关系行 1：人 → 书   的关系特征
```

这里的“关系特征”可以包含主体外观、客体外观、两者共同区域、相对位置、类别语义等信息。构造过程在上一课展开。

需要分清：此时还没有完成“拿着”“看着”等关系分类。一行特征先代表一个待判断的物体对。这个物体对之后可以对应多个关系标签。

例如：

```text
一个物体对：人 → 杯子
一行输入特征：描述这个物体对的数字
可能的多个输出关系：人看着杯子、人拿着杯子
```

所以，两个关系标签不一定对应两行 Transformer 输入。把“物体对特征的行数”与“最后的关系三元组数量”分清楚，后面的张量就容易理解。

### 2. 一行特征可以叫一个 token

论文经常使用 `token`。在本课中，你可以把它理解为：**交给注意力模块处理的一项输入，这一项用一行特征表示。**

```text
第 0 个 token：人 → 杯子，一行 D 维特征
第 1 个 token：人 → 书，一行 D 维特征
```

这两个 token 都属于第 0 帧。空间模块让它们交换信息。时间模块把相邻帧中的关系 token 放在一起，继续交换信息。

“一个 token”只是数据单位的说法。它可以来自单词、图像小块、物体或物体对；本模型使用关系特征。

### 3. 固定本课的记号

| 记号 | 含义 | 本课练习中的值 |
| --- | --- | --- |
| `T` | 当前输入的视频帧数量 | 3 |
| `R` | 所有帧合计的关系特征行数 | 5 |
| `n_t` | 第 `t` 帧的关系特征数量 | 2、1、2 |
| `L` | 每帧关系数量的最大值 | 2 |
| `D` | 每行关系特征的维数 | 教学代码为 8；官方配置为 1936 |
| `H` | 注意力头数 | 教学代码为 2；官方顶层默认配置为 8 |
| `d_h` | 每个注意力头的维数 | `D / H` |

关系数量的总和满足：

$$
R = \sum_{t=0}^{T-1} n_t
$$

本课例子：

$$
R = 2 + 1 + 2 = 5,\qquad L = \max(2,1,2)=2
$$

不要把 `L` 当成总关系数量。它只表示一帧最多需要多少个位置。

## 二、为什么关系特征要交换信息

只看“人 → 杯子”的局部区域，有时很难判断这个人在做什么。画面中其他关系可能提供线索，例如“人 → 椅子”“人 → 桌子”。同一视频前后帧中的关系也可能让当前判断更稳定。

注意力做的事情是：针对当前关系，给允许访问的其他关系分配权重，然后把这些关系提供的信息加权组合起来。

```text
当前关系的一行特征
          ↓
计算它与其他关系的匹配分数
          ↓
将分数转换为权重
          ↓
按权重融合其他关系的信息
          ↓
得到含有上下文的新特征
```

注意力权重表示“模型此次计算中给哪项信息多大的权重”。它本身没有直接等同于“拿着”的概率，也没有直接表示“这条场景图边存在”的概率。真正的关系类别还要交给后续分类层预测。

## 三、Q、K、V 怎样产生

### 1. 先给名字对应含义

| 名称 | 中文 | 在计算中的作用 |
| --- | --- | --- |
| Query，Q | 查询 | 当前关系用什么表达去匹配其他关系 |
| Key，K | 键 | 每个关系提供什么表达供查询匹配 |
| Value，V | 值 | 匹配完成后实际被加权汇总的信息 |

可以用“查询与键决定权重，值提供内容”来记忆。

这些含义帮助你理解计算，但不要想象成程序里有人手工给每个关系写了一段问题和答案。Q、K、V 都是数字特征，是模型通过可学习的线性投影产生的。

### 2. 同一份输入经过三组不同的参数

先忽略偏置，用数学中的权重排列写：

$$
Q = X W_Q,\qquad K = X W_K,\qquad V = X W_V
$$

其中：

```text
X：原来的关系特征
W_Q：学习怎样生成查询
W_K：学习怎样生成键
W_V：学习怎样生成值
```

假设一个帧中有 `n` 个关系，每行 `D` 维；单个头的维数为 `d_h`：

```text
X   ：[n, D]
W_Q ：[D, d_h]
Q   ：[n, d_h]
```

K、V 同理。本节采用数学乘法约定；如果你把投影写成 `nn.Linear`，其内部参数 `weight` 保存为 `[输出维数, 输入维数]`，前向要理解为 `X @ weight.T + bias`。

含偏置时，例如：

$$
Q = X W_Q + b_Q
$$

偏置沿每一行广播。Q、K、V 通常各有自己的投影参数和偏置。

### 3. “自注意力”不意味着 Q、K、V 数值相同

空间层的接口调用形式是：

```python
输出, 权重 = 注意力(输入, 输入, 输入)
```

三个参数传入的是同一个输入张量。但 `nn.MultiheadAttention` 内部还会分别生成 Q、K、V。由于三组投影参数不同，生成后的 Q、K、V 一般也不同。

所以应该这样理解：

```text
同一组关系特征
   ├─ 查询投影 → Q
   ├─ 键投影   → K
   └─ 值投影   → V
```

“自”表示查询和被访问的信息来自同一组关系，不表示所有内部计算都使用同一组参数。

在配套代码中，我们把原始特征交给 `nn.MultiheadAttention`，让它完成内部投影。手算部分则直接给定已经生成的 Q、K、V，帮助你专注于权重和加权求和。

## 四、把注意力完整手算一遍

### 1. 给定一个查询、两个键、两个值

取单头的维数为 2：

$$
Q = \begin{bmatrix}1 & 0\end{bmatrix}
$$

$$
K = \begin{bmatrix}1&0\\0&1\end{bmatrix},\qquad
V = \begin{bmatrix}10&0\\0&20\end{bmatrix}
$$

这表示当前只有一个查询，要访问两个信息来源：

```text
查询 q  ：[1, 0]
第一个键：[1, 0]，对应的值：[10, 0]
第二个键：[0, 1]，对应的值：[0, 20]
```

K、V 的行必须对齐：第一个键对应第一个值，第二个键对应第二个值。

### 2. 用点积得到匹配分数

第一个匹配分数：

$$
q\cdot k_1 = 1\times1 + 0\times0 = 1
$$

第二个匹配分数：

$$
q\cdot k_2 = 1\times0 + 0\times1 = 0
$$

整体矩阵乘法：

$$
QK^\top = \begin{bmatrix}1 & 0\end{bmatrix}
$$

形状跟踪：

```text
Q       ：[1, 2]
K       ：[2, 2]
K.T     ：[2, 2]
Q @ K.T ：[1, 2]
```

结果的每一列对应一个被访问的键。

### 3. 除以根号下的头维数

使用缩放点积：

$$
S = \frac{QK^\top}{\sqrt{d_h}}
$$

此处 `d_h=2`，所以：

$$
S = \begin{bmatrix}1/\sqrt{2} & 0\end{bmatrix}
\approx \begin{bmatrix}0.7071 & 0\end{bmatrix}
$$

随着维数增加，许多乘积相加，点积分数的尺度可能变大。这一缩放使分数的尺度更容易控制。你现在先掌握公式中除的是每个头的维数的平方根，而不是帧数、关系数量或整个多头特征的维数。

### 4. 沿“被访问的键”做 softmax

对这一个查询对应的两个分数：

$$
a_1 = \frac{e^{0.7071}}{e^{0.7071}+e^0}
\approx 0.6698
$$

$$
a_2 = \frac{e^0}{e^{0.7071}+e^0}
\approx 0.3302
$$

所以：

$$
A = \operatorname{softmax}(S)
\approx \begin{bmatrix}0.6698 & 0.3302\end{bmatrix}
$$

一行权重的和为 1。这里把第一个信息来源分配到约 66.98% 的权重，第二个分配到约 33.02%。

代码：

```python
权重 = torch.softmax(分数, dim=-1)
```

`dim=-1` 指最后一维。本例的最后一维正好列出两个被访问的键。

### 5. 对值加权求和

$$
Z = AV
$$

$$
Z = 0.6698\,[10,0] + 0.3302\,[0,20]
\approx [6.6976,6.6048]
$$

形状：

```text
A     ：[1, 2]
V     ：[2, 2]
A @ V ：[1, 2]
```

最终是这个查询的新特征。要加权的是 V，而不是重新对 K 加权。K 已经参与了计算权重。

这里的两个值和投影只是教学数字。真实训练时，模型学习它们应该包含什么信息。

### 6. 多个查询一起算

如果一个帧中有 `n` 个关系，并且每个关系都作为查询：

```text
Q：[n, d_h]
K：[n, d_h]
V：[n, d_h]
S：[n, n]
A：[n, n]
Z：[n, d_h]
```

`A[i,j]` 表示第 `i` 个关系访问第 `j` 个关系时的权重。每一行属于一个查询，每一列属于一个键。

例如：

```text
            被访问关系 0   被访问关系 1
查询关系 0       0.8            0.2
查询关系 1       0.3            0.7
```

两个查询可以给同一个信息来源不同的权重。权重矩阵一般不对称，不能假设 `A[0,1]` 必然等于 `A[1,0]`。

## 五、多头注意力怎样接起来

### 1. 每个头各学一套匹配方式

单个头按照上面的流程工作。多头注意力并行使用多组投影，让不同头能够学习不同的信息组合方式。

你可以把它理解为多个可学习的观察角度。但不能事先断言第一个头必然学颜色、第二个头必然学位置；这些功能由训练决定，未必按人能命名的方式分开。

官方顶层 `transformer` 默认 `embed_dim=1936`、`nhead=8`：

$$
d_h = 1936/8 = 242
$$

因此每个头处理 242 维查询、键和值。缩放因子是 `sqrt(242)`，约 15.56。

本课代码采用 `D=8`、`H=2`，所以每个头处理 4 维。这样既保留多头结构，又能在 CPU 上快速完成。

### 2. 拼接各个头，然后做输出投影

对第 `h` 个头：

$$
Z_h = \operatorname{softmax}\left(\frac{Q_hK_h^\top}{\sqrt{d_h}}\right)V_h
$$

各个头的结果拼接：

$$
Z_{\text{concat}} = \operatorname{Concat}(Z_1,\ldots,Z_H)
$$

再经过一组输出投影：

$$
O = Z_{\text{concat}}W_O + b_O
$$

以官方维数为例：

```text
第 1 个头：[n, 242]
第 2 个头：[n, 242]
……
第 8 个头：[n, 242]
     ↓ 沿特征维拼接
拼接结果：[n, 1936]
     ↓ 输出线性投影
注意力输出：[n, 1936]
```

`W_O` 会混合不同头的信息。多头结果并非仅仅拼接后直接交给分类器。

### 3. 注意力层有哪些可学习参数

常见参数包括查询、键、值的投影权重与偏置，以及输出投影的权重与偏置。`nn.MultiheadAttention` 为效率把若干参数保存在合并的张量中。

当 `kdim`、`vdim` 与 `embed_dim` 相同时，常见形状为：

```text
in_proj_weight：[3D, D]  # Q、K、V 三组投影合在一起
in_proj_bias  ：[3D]
out_proj.weight：[D, D]
out_proj.bias  ：[D]
```

不要看到一个合并参数就以为 Q、K、V 共用同一组权重。合并是保存方式，三个投影仍占用不同的参数区间。

## 六、先读懂 PyTorch 注意力接口的形状

本课与官方代码都采用 `batch_first=False` 的排列：

```text
[序列长度, 批量数量, 特征维数]
```

例如：

```python
注意力 = torch.nn.MultiheadAttention(embed_dim=8, num_heads=2)
```

若输入形状是 `[2,3,8]`，三个数字分别代表：

```text
2：每个序列有两个位置
3：一次并行计算三个序列
8：每个位置有八个特征数字
```

在空间模块中，这三个序列分别是三帧；在时间模块中，批量维分别表示多个相邻帧窗口。这里“批量”是注意力计算并行的单位，不一定等于训练时加载了几个视频。

注意力的输出保持同样的查询序列形状。默认返回的权重已经对注意力头求平均：

```text
输出：[查询长度, 批量数量, D]
权重：[批量数量, 查询长度, 键长度]
```

如果传入 `average_attn_weights=False`，权重才额外包含头数维：

```text
[批量数量, H, 查询长度, 键长度]
```

不要因为返回权重中没有头数维就以为模型用了一个头；也不要拿平均后的权重去声称某一个具体头的行为。

## 七、残差相加：保留原特征，再加入新信息

注意力生成新信息 O 后，空间层不是简单丢弃输入 X，而是做：

$$
U = X + \operatorname{Dropout}(O)
$$

这就是残差相加。

简单数字例子：

```text
原特征 X：[2, 5]
新信息 O：[0.3, -0.2]
相加结果：[2.3, 4.8]
```

这里没有先把两个向量拼成四维。相加要求两者形状兼容，最终仍是两维。

在模型中，残差让模块学习对现有特征的修改，也给梯度提供更直接的传播路径。它没有自动保证训练不出问题，但解释了为什么注意力输出需要保留 D 维：这样才能与输入逐位置相加。

这条计算也不是参数更新。`X + O` 属于模型的前向计算，训练时要记录计算图，不应该随意包进 `torch.no_grad()`。

## 八、Dropout 具体做什么

训练时，Dropout 随机把一部分输入位置变为 0，并对保留下来的值做缩放。设丢弃概率为 `p`：

$$
\operatorname{Dropout}(x_i)=
\begin{cases}
0,&\text{以概率 }p\text{ 丢弃}\\
x_i/(1-p),&\text{以概率 }1-p\text{ 保留}
\end{cases}
$$

例如 `p=0.1`，保留的值会乘 `1/0.9`。这样在随机性的平均意义上保持原有数值尺度。

空间和时间层中有不同位置的 Dropout，包括注意力模块内部，以及注意力输出和前馈层附近。它们的作用位置要按实际代码看。

调用 `模型.eval()` 后，Dropout 停止随机丢弃，前向结果更适合稳定评估。`eval()` 没有关闭自动求导；`torch.no_grad()` 才负责关闭特定上下文里的梯度记录。

本课代码为方便核对，把 Dropout 概率设为 0。官方默认配置为 0.1。不要将练习中可重复的数字当成完整项目采用了零 Dropout。

## 九、LayerNorm 归一化谁

### 1. 对每个关系自己的特征维做归一化

设一个 token 的特征为：

$$
x=[x_1,x_2,\ldots,x_D]
$$

均值：

$$
\mu=\frac{1}{D}\sum_{i=1}^{D}x_i
$$

方差：

$$
\sigma^2=\frac{1}{D}\sum_{i=1}^{D}(x_i-\mu)^2
$$

归一化并做可学习的缩放、平移：

$$
y_i=\gamma_i\frac{x_i-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta_i
$$

`nn.LayerNorm(D)` 归一化输入的最后一个维度。对于 `[L,T,D]` 输入，它分别处理每个 `[D]` 特征向量。

```text
关系 0 的 D 个数字 → 用关系 0 自己的均值与方差
关系 1 的 D 个数字 → 用关系 1 自己的均值与方差
```

它不会先把所有帧、所有关系的数字汇总成一个全局均值。

### 2. 用 [1,3] 手算

均值：

$$
\mu=(1+3)/2=2
$$

方差：

$$
\sigma^2=((1-2)^2+(3-2)^2)/2=1
$$

若先取 `gamma=1`、`beta=0`、`epsilon=1e-5`：

$$
y=\left[\frac{-1}{\sqrt{1+10^{-5}}},
\frac{1}{\sqrt{1+10^{-5}}}\right]
\approx [-1,1]
$$

`epsilon` 是防止分母为 0 的小正数，因此输出不是数学上恰好等于整数的 `[-1,1]`。

### 3. 手算方差要除以 D

PyTorch LayerNorm 使用总体方差形式，分母是 D。在我们当前的 PyTorch 环境中核对时应写：

```python
方差 = 输入.var(dim=-1, correction=0, keepdim=True)
```

不要直接套用默认带样本方差修正的 `var()`，否则 `[1,3]` 的方差会不同，和 LayerNorm 的结果对不上。

### 4. gamma 和 beta 是模型参数

```text
gamma：每个特征位置的可学习缩放系数
beta ：每个特征位置的可学习平移系数
```

默认初始化为 `gamma=1`、`beta=0`。训练后可以改变，所以 LayerNorm 的最终输出未必一直保持均值 0、方差 1。

在训练模式和评估模式下，LayerNorm 都使用当前输入自身的统计量。它没有像某些归一化层一样依赖训练时累计的运行均值。

## 十、前馈网络 FFN 为什么还有两层线性层

注意力让不同 token 之间交流，前馈网络继续加工每个 token 的特征：

$$
\operatorname{FFN}(x)=
\operatorname{Linear}_2\left(
\operatorname{Dropout}\left(
\operatorname{ReLU}(\operatorname{Linear}_1(x))\right)\right)
$$

官方维数为：

```text
一行 1936 维
    ↓ Linear 1
一行 2048 维
    ↓ ReLU
一行 2048 维
    ↓ Dropout
一行 2048 维
    ↓ Linear 2
一行 1936 维
```

ReLU 定义为：

$$
\operatorname{ReLU}(a)=\max(0,a)
$$

例如 `[1,-2,3]` 经过 ReLU 得到 `[1,0,3]`。

它让模型具有非线性。若两层线性层之间没有任何非线性，只是连续做两个线性映射，可以合并成一个线性映射，表达能力的结构会不同。

为了手算，取输入 `[2,1]`，让第一层输出 `[2-1,-2+1]=[1,-1]`；ReLU 得到 `[1,0]`；第二层假设暂时为恒等映射，则输出 `[1,0]`。这只是人为选择参数的算术例子，真实权重由训练学习。

FFN 的同一组参数应用到所有 token。它不会在 FFN 内部再把关系 0 和关系 1 做点积；直接跨 token 的信息融合来自注意力。FFN 加工的输入已经可以含有先前融合得到的上下文信息。

## 十一、空间模块的真实执行顺序

空间层使用同一帧中的关系作为自注意力输入。按官方实现顺序写成公式：

$$
O=\operatorname{MHA}(X,X,X;\text{padding mask})
$$

$$
U=\operatorname{LN}_1(X+\operatorname{Dropout}_1(O))
$$

$$
F=\operatorname{Linear}_2\big(
\operatorname{Dropout}(\operatorname{ReLU}(\operatorname{Linear}_1(U)))\big)
$$

$$
Y=\operatorname{LN}_2(U+\operatorname{Dropout}_2(F))
$$

用流程图式文字记忆：

```text
输入
  ↓ 同帧多头注意力
注意力结果
  ↓ Dropout + 与输入残差相加
  ↓ LayerNorm 1
  ↓ Linear 1 → ReLU → Dropout → Linear 2
  ↓ Dropout + 与第一次归一化结果残差相加
  ↓ LayerNorm 2
输出
```

两个 LayerNorm 是两个独立模块，各有自己的参数。不能因为它们公式相同就当成同一个参数对象。

这一层不会改变每帧实际关系数量，也不会产生新的物体实例编号；它更新每一行特征，使其含有同帧的关系上下文。

## 十二、不同帧的关系数量不同，怎样并行计算

### 1. 原始输入是所有关系的一张表

本课三个帧的关系数量是 `[2,1,2]`：

| 原始行号 | 属于哪帧 | 对应的一行关系特征 |
| --- | --- | --- |
| 0 | 第 0 帧 | `r0` |
| 1 | 第 0 帧 | `r1` |
| 2 | 第 1 帧 | `r2` |
| 3 | 第 2 帧 | `r3` |
| 4 | 第 2 帧 | `r4` |

输入：

```text
features：[R,D] = [5,8]
im_idx  ：[R]   = [0,0,1,2,2]
```

`im_idx[i]` 回答“第 i 行关系特征属于哪一帧”。它不是物体类别，不是关系类别，也不是追踪 ID。

### 2. 找到最大数量 L，再补齐

`L=2`，因此三帧都暂时分配两个序列位置：

```text
                  第 0 帧       第 1 帧       第 2 帧
序列位置 0          r0            r2            r3
序列位置 1          r1            补齐          r4
```

空间输入形状：

```text
[L,T,D] = [2,3,8]
```

补齐位置用零向量填充，但这个零向量并不是一个真实关系。

### 3. 用掩码说明哪些位置没有真实关系

`key_padding_mask` 形状是 `[T,L]`：

```text
第 0 帧：[False, False]
第 1 帧：[False, True ]
第 2 帧：[False, False]
```

在 `nn.MultiheadAttention` 的布尔 `key_padding_mask` 中：

```text
False：可以作为 key/value 被访问
True ：这是补齐位置，不能作为有效 key/value 被访问
```

注意输入和掩码的前两维顺序不同：

```text
输入：[L,T,D]
掩码：[T,L]
```

这是该接口规定的形状。不要仅凭“它们应该对齐”就把掩码写成 `[L,T]`。

### 4. 为什么填零还需要掩码

没有掩码时，补齐位置可能仍参与 softmax 的分母，分走一部分权重。即使其最初的值为零，线性投影的偏置、残差、归一化等也可能让后续值不为零。

如果一个有效查询与两个真实 key 的分数是 `[1,0]`，另外补齐 key 的分数也是 0：

```text
不屏蔽：softmax([1,0,0])，三项竞争权重
屏蔽后：只让前两项参与，补齐那一项权重为 0
```

从算术上看，通常相当于在对应分数上加负无穷，再做 softmax：

$$
e^{-\infty}=0
$$

补齐位置被排除，权重才分配给真实信息。

### 5. key_padding_mask 不保证补齐 query 的输出是零

这里的掩码主要屏蔽被访问的 key。补齐位置如果也作为 query，仍可能查询真实 key，并得到非零结果。

配套代码中第 1 帧的权重矩阵会出现：

```text
[[1,0],
 [1,0]]
```

第一行属于真实 query，第二行属于补齐 query。两行都只能访问第一个真实 key。我们最终只保留真实 query 的结果，因此第二行会被丢弃。

不要写出“mask 为 True，因此那一整行输出必然为零”的推断。需要根据掩码类型区分屏蔽 key、屏蔽 query 或屏蔽特定 query-key 配对。

### 6. 旧代码与当前练习的掩码类型

官方历史代码构造空间掩码时使用 `torch.uint8`。我们的当前环境使用布尔掩码 `torch.bool`，配套代码已采用这种形式。

核心语义相同：在这个接口中，补齐位置被屏蔽。不要将它与其他库或者其他函数的掩码语义混用。

若整个序列都没有有效 key，softmax 等计算可能产生无效数值。真实复现时要阅读数据如何筛选视频和帧；本课人工样例每帧至少有一个关系，避免把这个边界情况藏进练习。

## 十三、空间结果怎样恢复成 [R,D]

空间模块输出仍是 `[L,T,D]`。要把它恢复到原来的关系表：

```text
[2,3,8] → 去掉第 1 帧的补齐位置 → [5,8]
```

官方实现先交换前两维：

```text
[L,T,D] → [T,L,D]
```

这样展平后按帧排列：

```text
第 0 帧位置 0 → r0
第 0 帧位置 1 → r1
第 1 帧位置 0 → r2
第 1 帧位置 1 → 补齐
第 2 帧位置 0 → r3
第 2 帧位置 1 → r4
```

再用展平后的掩码保留真实位置，得到 `[r0,r1,r2,r3,r4]` 的新特征。

这套展平还原方式依赖输入行已经按帧分组，并且组内顺序保持一致。它没有凭空理解哪个特征属于哪个物体对。

教学代码额外保存原始行号：

```text
[[0, 2, 3],
 [1,-1, 4]]
```

每一列是一帧，`-1` 表示没有原始行。还原时明确按行号放回，方便你观察输入和输出的对应关系。

无论用哪种写法，都应检查：最终第 i 行仍然对应原来的第 i 个物体对。关系特征与标签一旦错位，模型即使正常反向传播，也是在拿错误答案训练。

## 十四、时间模块怎样构造相邻帧窗口

### 1. 空间结果已经融入同帧上下文

现在拿到空间输出表：

```text
第 0 帧：r0'、r1'
第 1 帧：r2'
第 2 帧：r3'、r4'
```

加撇号表示数值已经更新，物体对的行号仍然不变。

时间模块继续使用这些关系特征，不是重新把原图送进检测器。

### 2. 窗口大小为 2，步长为 1

三帧形成两个窗口：

```text
窗口 0：第 0 帧 + 第 1 帧
窗口 1：第 1 帧 + 第 2 帧
```

如果视频有四帧：

```text
窗口 0：(0,1)
窗口 1：(1,2)
窗口 2：(2,3)
```

窗口数量是 `T-1`。中间帧会出现在前后两个窗口中。

这是一种固定局部窗口的组织方式。官方模块不是把整段视频的全部关系直接拼成一个无限长的时间序列。

### 3. 每个窗口最多需要 2L 个位置

一帧最多 L 个关系，两帧最多 2L 个。因此时间输入形状是：

```text
[2L,T-1,D]
```

本课：

```text
[4,2,8]
```

两个窗口分别包含三个真实关系，最后补齐一个位置：

| 窗口内位置 | 窗口 0：帧 0、1 | 窗口 1：帧 1、2 |
| --- | --- | --- |
| 0 | `r0'`，属于帧 0 | `r2'`，属于帧 1 |
| 1 | `r1'`，属于帧 0 | `r3'`，属于帧 2 |
| 2 | `r2'`，属于帧 1 | `r4'`，属于帧 2 |
| 3 | 补齐 | 补齐 |

关键细节：较早帧的真实关系先放，较晚帧的真实关系紧接着放。它们没有强制各占 L 个固定位置再在中间插入补齐。

例如窗口 1 的较早帧只有一个关系，因此较晚帧从位置 1 开始，不是必须从位置 L=2 开始。

### 4. 时间掩码按窗口排列

时间 `key_padding_mask` 的形状：

```text
[T-1,2L] = [2,4]
```

本例两行都是：

```text
[False,False,False,True]
```

这个掩码屏蔽补齐关系。它并没有屏蔽“来自较晚帧的真实关系”。

### 5. 保存窗口索引，才能正确还原

我们为每个位置保存原始行号：

```text
                窗口 0     窗口 1
位置 0             0           2
位置 1             1           3
位置 2             2           4
位置 3            -1          -1
```

同时保存绝对帧编号：

```text
                窗口 0     窗口 1
位置 0             0           1
位置 1             0           2
位置 2             1           2
位置 3            -1          -1
```

第一张表回答“对应原来的第几行关系”，第二张表回答“来自视频的第几帧”。这两种编号作用不同，不要混用。

## 十五、时间位置向量怎样使用

### 1. 两个可学习向量表示窗口中的前后位置

官方定义 `nn.Embedding(2,D)`，保存两行位置向量：

```text
p0：窗口里较早帧的位置向量
p1：窗口里较晚帧的位置向量
```

每个向量有 D 维，是可学习参数。官方初始化使用均匀分布。

这两个向量不是整段视频中帧 0 和帧 1 专属的绝对编号。它们表示窗口内部的相对位置。

所以同一关系 `r2'`：

```text
在窗口 0：(帧 0,帧 1)，它属于较晚帧，使用 p1
在窗口 1：(帧 1,帧 2)，它属于较早帧，使用 p0
```

### 2. 同一帧的关系共用对应的位置向量

窗口 0 的位置向量：

```text
位置 0：p0，对应 r0'
位置 1：p0，对应 r1'
位置 2：p1，对应 r2'
位置 3：零向量，补齐
```

窗口 1：

```text
位置 0：p0，对应 r2'
位置 1：p1，对应 r3'
位置 2：p1，对应 r4'
位置 3：零向量，补齐
```

同一帧的不同关系仍可以有不同的查询和键，因为它们的关系特征不同；共享位置向量只表示它们处于同一种帧位置。

### 3. 官方把位置加到 query 和 key 的接口输入上

若时间窗口特征是 G、位置向量是 P：

```python
输出, 权重 = 注意力(
    query=G + P,
    key=G + P,
    value=G
)
```

接口内部继续分别做可学习投影。所以完整理解为：

$$
Q=(G+P)W_Q+b_Q
$$

$$
K=(G+P)W_K+b_K
$$

$$
V=GW_V+b_V
$$

不是提前生成 Q、K 后直接给它们加 P，也不是把 P 拼在 G 的后面增加维数。

尽管 query 和 key 的接口输入相同，它们经过不同投影后仍一般不同。值的接口输入没有直接加位置向量，但位置可以通过改变注意力权重影响最终汇总。

### 4. 位置向量也需要训练

当关系分类损失通过时间注意力反向传播时，梯度可以连到位置表的两个向量。它们会随着优化器更新。

配套练习也检查这一点，输出 `位置表梯度形状：(2,8)`。这说明位置向量是计算图中可学习的参数，而不是固定的人工时间戳。

## 十六、时间层的实际顺序与空间层不同

时间层的注意力：

$$
O=\operatorname{MHA}(G+P,G+P,G;\text{padding mask})
$$

第一段残差和归一化：

$$
U=\operatorname{LN}_3(G+\operatorname{Dropout}_2(O))
$$

前馈网络：

$$
F=\operatorname{Linear}_2\big(
\operatorname{Dropout}(\operatorname{ReLU}(\operatorname{Linear}_1(U)))\big)
$$

最后一段残差：

$$
Y=U+\operatorname{Dropout}_3(F)
$$

官方这份实现中，最后没有再调用第二个 LayerNorm。

| 操作 | 空间层 | 时间层 |
| --- | --- | --- |
| query、key、value 的接口输入 | 都是 X | query、key 为 G+P；value 为 G |
| 注意力后残差相加 | 有 | 有 |
| 第一次 LayerNorm | 有 | 有 |
| 两层线性组成的 FFN | 有 | 有 |
| FFN 后残差相加 | 有 | 有 |
| 第二次 LayerNorm | 有 | 这份实现没有 |

不要根据一般 Transformer 的示意图自行补一个不存在的归一化层。读论文时可以先理解通用模块，复现时必须回到作者实际实现。

官方顶层模块的默认参数是 1 层空间层和 3 层时间层。各层参数独立；上一层的输出继续交给下一层。在每个时间层中，同样的窗口位置向量再次参与 query 和 key 的输入。

层数是构建模型时的配置，不能只看到构造函数的默认值就忽略运行时传入的参数。检查实际模型创建语句和命令行设置，才能确认某次实验用了多少层。

## 十七、同一个关系出现在两个窗口，怎样保留结果

### 1. 先看重复出现的关系 r2

三帧例子：

```text
窗口 0：(0,1)，有 r0、r1、r2
窗口 1：(1,2)，有 r2、r3、r4
```

`r2` 属于第 1 帧，出现两次。两次输出一般不一样，因为窗口上下文和位置向量不同。

你不能把两个窗口的全部有效输出直接拼成最终关系表，否则会得到 6 行，重复计算同一个关系。最终需要回到原来的 5 行。

### 2. latter 模式

官方提供 `latter` 模式：通常每个窗口保留较晚帧的关系输出；第一个窗口还额外保留第 0 帧的关系输出。

本例：

| 最终属于哪帧 | 从哪个窗口取 | 取哪些关系 |
| --- | --- | --- |
| 帧 0 | 窗口 0 `(0,1)` | `r0`、`r1` |
| 帧 1 | 窗口 0 `(0,1)` | `r2` |
| 帧 2 | 窗口 1 `(1,2)` | `r3`、`r4` |

最终还原：

```text
[r0的新特征,r1的新特征,r2的新特征,r3的新特征,r4的新特征]
```

形状重新是 `[R,D]`。配套代码记录每一行被写入的次数，并验证每一行恰好写入一次。

### 3. both 模式

官方还提供 `both`：首帧取第一个窗口，末帧取最后一个窗口；中间帧在前后两个窗口中的输出做平均。

本例中：

$$
r2_{\text{最终}} = \frac{r2_{\text{窗口0}}+r2_{\text{窗口1}}}{2}
$$

平均的是同一个原始关系在不同窗口中的特征，不是把两帧中任意两条关系混在一起平均。

学习时先掌握 `latter`；阅读项目时再确认它实际选择哪一种。两种模式会让最终每行特征利用到的上下文不同。

## 十八、必须澄清的三个时间建模问题

### 1. latter 不等于因果注意力

时间掩码只屏蔽补齐位置，没有给 query-key 配对施加“不能看后面帧”的因果约束。

尤其第 0 帧的关系也在窗口 `(0,1)` 中计算，可以访问第 1 帧的真实关系。因此整套实现不能被称为严格只使用过去信息的在线模型。

`latter` 说明最终如何选取重复的输出，不是限制注意力可访问范围的因果掩码。

这里的任务是对已给定的视频帧生成场景图。对“尚未看到的未来帧进行预测”是另一种任务，不能因为模型包含时间模块就自动认为它能够完成未来预测。

### 2. 不会自动按追踪 ID 对齐同一个物体

窗口把两帧中的全部有效关系放在一起，让它们通过注意力学习关联。这个模块没有规定：第一帧第 0 个关系只能访问第二帧第 0 个关系。

```text
较早帧关系 0 可以访问：
较早帧的其他关系 + 较晚帧的全部有效关系
```

空间、语义和视觉特征可能帮助模型找到有意义的关联，但这不等同于程序已经匹配好了物体轨迹。

`im_idx` 保存帧编号。它不能告诉你两帧中的杯子是不是同一个杯子。若另一个方法加入显式追踪，需要单独阅读它怎样维护实例关联。

### 3. decoder 这个名字不代表语言生成

官方把时间模块称为 `TransformerDecoder`。它没有在这里逐个生成词，没有自回归地输出关系，也没有标准编码器—解码器结构中的另一组外部 memory cross-attention。

它把空间输出整理成两帧窗口，进行带时间位置向量的关系注意力，然后把结果还原。

所以读类名时，应继续看 `forward()` 的参数和计算。类名提供线索，实际数据流决定这个模块做什么。

## 十九、如何判断补齐位置

本课教学代码使用明确记录的有效位置来构造时间掩码。只要位置来自真实关系，就标记为有效；补齐的位置才标记为屏蔽。

官方历史实现的时间掩码使用“这一行特征的数字之和是否为 0”来推断补齐。你阅读时需要知道这是它的实现方式，但不要把“数字和为 0”当成所有模型普遍可靠的有效性定义。

反例：

```text
真实特征：[1,-1]
数字之和：0
```

它是一行真实特征，却和补齐零向量都满足求和为 0。明确保存有效数量或有效索引，可以让教学中的判断更直观，也不会受特征数值影响。

这说明本课练习用于解释结构，并非逐字复制官方项目。真实复现时若修改掩码构造，应记录改动及理由，而不能将不同实现的实验结果直接当成完全相同配置。

| 最终还原 | 使用 latter 方式恢复 `[5,8]` |
| 梯度检查 | 确认人工输入、注意力参数、位置表能收到梯度 |

代码没有使用图片读取、物体检测和真实关系标签。最后的平方平均只是为了检查计算图，不能称为项目的关系分类损失。

## 二十一、把模块接回整个关系预测流程

完整关系特征为 `[R,1936]` 时，模型大体执行：

```text
构造关系特征 [R,1936]
          ↓ 用 im_idx 按帧打包
空间输入 [L,T,1936]
          ↓ 空间注意力与前馈层
空间输出 [L,T,1936]
          ↓ 去掉补齐，恢复关系顺序
同帧上下文特征 [R,1936]
          ↓ 构造相邻两帧窗口与位置向量
时间输入 [2L,T-1,1936]
          ↓ 时间注意力与前馈层
时间输出 [2L,T-1,1936]
          ↓ 根据窗口还原策略选择结果
最终关系特征 [R,1936]
          ↓ 多组关系分类层
对应各个物体对的关系预测
```

注意力模块输出的 1936 个数字仍是特征。后面的线性分类层才把它们映射到具体类别数量的得分。

训练时，关系损失的梯度可以沿着分类层、时间模块、空间模块回传，更新其中的可学习参数。哪些更早的图像特征提取模块参与更新，则要看完整项目的训练设置和冻结方式。

## 二十二、练习：先遮住答案，自己手算

### 练习 1：token 与标签

一个人和一只杯子形成一个物体对，标注了“看着”和“拿着”两个关系。为了描述这个物体对，应该自动构造两行完全独立的 Transformer 输入吗？

<details>
<summary>参考答案</summary>

不能仅凭两个标签就断定需要两行。STTran 的关系特征按待判断的物体对构造，一行特征可以用于预测多个关系标签。要区分关系特征的行数与输出三元组数量。

</details>

### 练习 2：Q、K、V

调用 `注意力(X,X,X)`，是否可以认定内部 `Q==K==V`？

<details>
<summary>参考答案</summary>

不可以。它们的接口输入相同，但内部查询、键、值分别经过不同的可学习投影，生成后的数值通常不同。

</details>

### 练习 3：注意力矩阵的维数

单个头中 Q 为 `[3,4]`，K 为 `[5,4]`，V 为 `[5,6]`。`Q @ K.T`、权重矩阵、加权结果分别什么形状？

<details>
<summary>参考答案</summary>

K.T 为 `[4,5]`，分数与权重均为 `[3,5]`；权重乘 V 后为 `[3,6]`。每个查询可以访问 5 个 key/value 对。这个例子用来练习一般注意力的形状，V 的维数可以与 Q/K 不同；本课多头配置使用固定头维数。

</details>

### 练习 4：加权求和

权重为 `[0.25,0.75]`，两个值为 `[4,0]`、`[0,8]`，加权结果是多少？

<details>
<summary>参考答案</summary>

`0.25×[4,0] + 0.75×[0,8] = [1,6]`。

</details>

### 练习 5：多头维数

`D=1936`，`H=8`，每个头多少维？缩放点积除以什么？

<details>
<summary>参考答案</summary>

每头 242 维；除以 `sqrt(242)`。拼接八个头恢复 1936 维，随后还要经过输出投影。

</details>

### 练习 6：残差相加

输入 `[2,5]`，注意力结果 `[0.3,-0.2]`，忽略 Dropout 和归一化。残差相加结果及维数是多少？

<details>
<summary>参考答案</summary>

结果 `[2.3,4.8]`，仍是两维。残差是逐项相加，不是拼接。

</details>

### 练习 7：LayerNorm 范围

输入 `[2,3,8]`，调用 `nn.LayerNorm(8)`。它把全部 48 个数一起求均值吗？

<details>
<summary>参考答案</summary>

不会。最后一维为 8，因此分别对 6 个长度为 8 的特征向量求各自的均值与总体方差。前两个维度保持独立。

</details>

### 练习 8：LayerNorm 方差

输入 `[2,4]`，均值与总体方差是多少？若忽略 epsilon、gamma=1、beta=0，输出是多少？

<details>
<summary>参考答案</summary>

均值为 3，方差为 `((2-3)^2+(4-3)^2)/2=1`，归一化后为 `[-1,1]`。真实实现加 epsilon，数值与整数会有微小差别。

</details>

### 练习 9：空间形状

四帧关系数量为 `[3,1,2,2]`，特征维数 8。R、L、空间输入、空间掩码的形状分别是多少？

<details>
<summary>参考答案</summary>

R=8，L=3；空间输入 `[3,4,8]`，空间掩码 `[4,3]`。四帧的掩码分别为 `[F,F,F]`、`[F,T,T]`、`[F,F,T]`、`[F,F,T]`，F 表示 False，T 表示 True。

</details>

### 练习 10：补齐 query

一个序列包含一个有效关系和一个补齐位置。屏蔽补齐 key 后，补齐 query 的输出是否必然为零？

<details>
<summary>参考答案</summary>

不必然。它仍可能查询那个有效 key，所以可能得到非零输出。最终应按有效位置去掉补齐 query 的输出。

</details>

### 练习 11：窗口数量

T=5，窗口大小 2，步长 1，一共有几个窗口？

<details>
<summary>参考答案</summary>

4 个：`(0,1)`、`(1,2)`、`(2,3)`、`(3,4)`。

</details>

### 练习 12：时间形状

沿用练习 9，时间输入和时间掩码分别什么形状？

<details>
<summary>参考答案</summary>

T=4、L=3、D=8；时间输入 `[6,3,8]`，时间掩码 `[3,6]`。三个窗口的有效数量分别为 4、3、4。

</details>

### 练习 13：位置向量

第 2 帧的一个关系，分别出现在窗口 `(1,2)` 和 `(2,3)`。两次使用哪个位置向量？

<details>
<summary>参考答案</summary>

在 `(1,2)` 中较晚，使用 p1；在 `(2,3)` 中较早，使用 p0。位置表描述窗口内部位置。

</details>

### 练习 14：latter 选哪次

五帧视频中，第 2 帧关系在两个窗口产生不同结果。latter 保留来自哪个窗口的结果？第 0 帧取哪里？

<details>
<summary>参考答案</summary>

第 2 帧取窗口 `(1,2)`；第 0 帧取第一个窗口 `(0,1)` 中属于第 0 帧的结果。这也说明第 0 帧可以利用第 1 帧信息。

</details>

### 练习 15：时间模块是不是跟踪器

`im_idx=[0,0,1,1]` 能否说明第 0 行和第 2 行对应同一个杯子？

<details>
<summary>参考答案</summary>

不能。它只说明前两行属于帧 0、后两行属于帧 1。相同实例的跨帧关联需要另外的信息和过程，帧编号本身不提供这种关联。

</details>

### 练习 16：归一化层数量

官方一个空间层和一个时间层分别有几个实际使用的 LayerNorm？

<details>
<summary>参考答案</summary>

空间层有两个，时间层有一个。时间层的第二次残差之后没有第二次归一化。

</details>

### 练习 17：判断有效性

如果真实特征是 `[2,-2]`，用“数字之和为 0”判断补齐会发生什么？

<details>
<summary>参考答案</summary>

可能把真实关系错误地标记为补齐。直接保存有效数量、掩码或原始行号更容易明确地表达数据有效性。

</details>

### 练习 18：注意力与关系分类

某个注意力权重为 0.9，是否能直接解释为“人拿着杯子的概率是 0.9”？

<details>
<summary>参考答案</summary>

不能。它表示某个查询对某个 key/value 信息的融合权重。关系类别概率需要后续分类层及其相应激活、任务定义共同决定。

</details>

### 修改 2：查看每个头的权重

给两个注意力调用加 `average_attn_weights=False`。空间权重现在应是 `[T,H,L,L]`，时间权重应是 `[T-1,H,2L,2L]`。

### 修改 3：开启 Dropout 后比较 train 与 eval

在两个层的注意力模块和相关位置加入实际 Dropout，先调用 `train()` 做两次前向，再调用 `eval()` 做两次前向。

随机丢弃开启时，连续两次结果通常不同；评估模式关闭随机丢弃后，在相同输入与参数下结果应稳定。本课固定脚本省略了概率为零的显式 Dropout 模块，因此要同时阅读本课公式和官方代码，再完成这项扩展。

注意力内部的 Dropout 可能改变训练时返回权重的数值尺度；不要在开启它后继续机械要求每一次返回的每行权重恰好求和为 1。

### 修改 4：实现 both 还原

保留首帧和末帧，给中间帧收集前后两个窗口的对应行，再求平均。检查最终行数仍为 R，不会因为关系在多个窗口出现而增加。

先用时间输入本身检验索引；确认还原正确后，再将真正的时间层输出送进去。这样能把“索引写错”和“模型数值发生变化”分开定位。

## 二十四、常见误区快速核对

| 容易误解的说法 | 正确理解 |
| --- | --- |
| 两个关系标签需要两行 token | 一行物体对特征可以预测多个关系标签 |
| Q、K、V 是手工指定的三个固定含义 | 实际是可学习投影产生的特征 |
| 自注意力说明 Q、K、V 相等 | 相同来源的输入经过不同投影 |
| softmax 是沿查询维做的 | 每个查询对它可访问的键分配权重 |
| 注意力权重是最终关系概率 | 它控制上下文信息融合 |
| 多头只是把输入随意切八份 | 包含可学习投影、分头计算、拼接与输出投影 |
| 残差相加增加特征长度 | 残差按位置相加，特征维数保持 |
| LayerNorm 对全部关系求一个均值 | `LayerNorm(D)` 分别对每行最后 D 维归一化 |
| LayerNorm 方差用 D-1 作分母 | 该层使用总体方差，分母为 D |
| gamma、beta 是固定常数 | 默认可学习，初始化为 1 和 0 |
| FFN 是又一次跨帧注意力 | 它逐 token 加工已有特征 |
| 输入与掩码前两维顺序必须相同 | 本接口输入 `[L,T,D]`，掩码 `[T,L]` |
| 补齐为零就不会影响计算 | 没有屏蔽时可能分走权重，投影偏置也会起作用 |
| key 被屏蔽后 query 输出必为零 | 补齐 query 仍可能读到有效 key，之后需丢弃 |
| 时间窗口每帧各固定占 L 个位置 | 有效关系紧接着排列，最后补齐 |
| 位置表存每帧的绝对编号 | 这里只存窗口中较早、较晚两个位置向量 |
| latter 限制只能访问过去 | 它是结果还原策略，模块没有因果屏蔽 |
| 时间模块显式追踪同一实例 | 它让窗口中有效关系通过注意力学习关联 |
| decoder 会逐项自回归生成关系 | 这里是窗口注意力和特征还原 |
| 照标准 Transformer 就能补全代码 | 必须核对作者实际的模块顺序与归一化位置 |

## 二十五、阅读官方代码时的具体路线

打开[官方 lib/transformer.py](https://github.com/yrcong/STTran/blob/main/lib/transformer.py)，依次寻找：

1. `TransformerEncoderLayer.forward`：确认空间层的注意力、残差和两次归一化。
2. `TransformerDecoderLayer.forward`：确认位置只加到 query/key 的接口输入，第二次残差后没有归一化。
3. `transformer.__init__`：确认维数、头数、层数，以及两行位置表。
4. `transformer.forward` 前半段：用 `im_idx` 将关系按帧打包，理解 `l` 和 `b` 的含义。
5. 空间输出的 `permute`、`view` 与掩码索引：观察怎样恢复关系表。
6. 相邻窗口循环：跟踪 `global_input`、`position_embed`、`idx`。
7. `mode == 'latter'` 和 `mode == 'both'`：核对最终关系表如何写回。
8. 返回值：分别是关系特征输出、时间注意力权重、空间注意力权重。

源码中的局部变量 `b` 在这段代码里表示视频帧数，不必然等于你熟悉的训练批量大小。`l` 表示一帧最大的关系数量，旁边的注释并不能替代你对实际计数对象的检查。

先在纸上画本课 `[2,1,2]` 的例子，再追源码，每次只回答三个问题：输入形状是什么、这一行操作改变了哪一维、输出的第 i 行仍对应哪个关系。这样比单独背类名更容易建立完整的数据流。
