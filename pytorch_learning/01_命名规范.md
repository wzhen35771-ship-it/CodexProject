# 学习文件与 Git 提交命名规范

## 1. 课程文件

使用两位序号、中文主题和文件类型：

| 类型 | 格式 | 例子 |
| --- | --- | --- |
| 讲义 | `序号_主题_讲义.md` | `01_张量_讲义.md` |
| 示例代码 | `序号_主题_示例.py` | `01_张量_示例.py` |
| 自己的作业 | `序号_主题_作业.py` | `01_张量_作业.py` |
| 保存的教学权重 | `序号_主题_权重.pt` | `09_保存与加载_权重.pt` |

同一课的讲义、示例和作业使用相同序号与主题。多个训练选项可在权重名最后增加选项，如 `04_标签损失与训练_权重_bce.pt`。

## 2. 学习入口和辅助文件

| 用途 | 名称 |
| --- | --- |
| 全部学习内容的入口 | [00_学习总览.md](00_学习总览.md) |
| 各专题的学习入口 | `00_学习指南.md` |
| 术语与公式速查 | `98_术语公式速查.md` |
| 完整合订教材 | `99_完整教材.md` |

第三、第四步的完整教材位于各自专题文件夹。工具文件使用既有约定：`requirements.txt`、`.gitignore`、`.venv/`；教学权重放在对应专题的 `outputs/`。

引用外部项目时沿用作者源码文件名，例如 STTran 的 `train.py`、`lib/sttran.py`，便于与官方代码对应。

## 3. Python 代码内部命名

文件名继续使用前面的中文课程格式。代码内部的函数、变量、参数、类和属性使用英文标识符，不使用中文标识符。

| 对象 | 规则 | 例子 |
| --- | --- | --- |
| 函数、变量、参数、属性 | 小写英文单词，以 `_` 分隔，即 `snake_case` | `train_small_model`、`loss_choice`、`relation_features` |
| 类 | 单词首字母大写，即 `PascalCase` | `SmallRelationClassifier`、`SpatialLayer` |
| 固定常量 | 大写英文单词，以 `_` 分隔 | `NUM_CLASSES` |

`__init__`、`forward` 等框架约定名称保持原样。公式中的 `x`、`W`、`Q`、`K`、`V` 以及常用库别名 `nn`、`F` 可以沿用数学和库的惯例。

中文讲解放在注释、文档字符串和输出文本中。函数定义与调用、关键字参数、属性引用以及 f-string 中的表达式必须使用一致的英文标识符。讲义中的配套代码也使用相同命名。

例如：

```python
def train_small_model(loss_choice):
    """根据选择的损失函数训练小模型。"""
    print("选择的损失函数：", loss_choice)
```

模型属性名会成为 `state_dict` 中的参数键。重命名这些属性后，旧权重需要按新旧名称对应关系转换参数键，或重新训练生成权重，再由新模型加载。

## 4. Git 提交标题

统一格式：

```text
学习：具体变更
```

标题写清动作和对象，例如：

- `学习：补充自动求导与训练课程`
- `学习：完善场景图与STTran完整教材`
- `学习：统一文件命名与阅读入口`

以一次提交实际包含的变更为准，避免只用“总体”“分类”这类难以判断内容的名称。
