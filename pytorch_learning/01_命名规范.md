# 学习文件与 Git 提交命名规范

## 1. 课程文件

使用两位序号、中文主题和文件类型：

| 类型 | 格式 | 例子 |
| --- | --- | --- |
| 讲义 | `序号_主题_讲义.md` | `01_张量_讲义.md` |
| 示例代码 | `序号_主题_示例.py` | `01_张量_示例.py` |
| 自己的作业 | `序号_主题_作业.py` | `01_张量_作业.py` |
| 保存的教学权重 | `序号_主题_权重.pt` | `09_保存与加载_权重.pt` |

同一课的讲义、示例和作业使用相同序号与主题。多个训练选项可在权重名最后增加选项，如 `04_标签损失与训练_权重_bce.pt`。

## 2. 学习入口和辅助文件

| 用途 | 名称 |
| --- | --- |
| 全部学习内容的入口 | [00_学习总览.md](00_学习总览.md) |
| 各专题的学习入口 | `00_学习指南.md` |
| 术语与公式速查 | `98_术语公式速查.md` |
| 完整合订教材 | `99_完整教材.md` |

第三、第四步的完整教材位于各自专题文件夹。工具文件使用既有约定：`requirements.txt`、`.gitignore`、`.venv/`；教学权重放在对应专题的 `outputs/`。

引用外部项目时沿用作者源码文件名，例如 STTran 的 `train.py`、`lib/sttran.py`，便于与官方代码对应。

## 3. Git 提交标题

统一格式：

```text
学习：具体变更
```

标题写清动作和对象，例如：

- `学习：补充自动求导与训练课程`
- `学习：完善场景图与STTran完整教材`
- `学习：统一文件命名与阅读入口`

以一次提交实际包含的变更为准，避免只用“总体”“分类”这类难以判断内容的名称。
