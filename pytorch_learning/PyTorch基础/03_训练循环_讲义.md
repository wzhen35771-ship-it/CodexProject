# 第三课：训练一个人工关系分类器

这课把前两课连成一个能独立运行的程序。输入是已知物体位置构成的二维特征，输出是三种互斥的人工关系类别。目标是验证训练代码能否拟合少量数据，并完成保存加载。

配套程序：[03_训练循环_示例.py](03_训练循环_示例.py)。它使用 CPU 和 12 条人工数据，无需下载。运行成功后才生成 `outputs/03_训练循环_权重.pt`。

这不是从像素生成场景图的 SGDet 模型，没有真实数据、物体检测、关系检索和标准 R/mR 评价。训练集全部分类正确只证明这个小任务和训练链路能工作，不代表真实场景图效果。

## 1. 输入和标签是什么

假设主语和宾语的物体框已经给定，我们已知它们的归一化中心坐标。用：

```text
dx = 主语中心 x - 宾语中心 x
dy = 主语中心 y - 宾语中心 y
输入特征：[dx, dy]
```

图片坐标通常 x 向右增大，y 向下增大。本课定义三个人工类别：

| 编号 | 名称 | 人工数据特点 |
| --- | --- | --- |
| 0 | 主语在宾语左侧 | dx 明显为负，dy 接近 0 |
| 1 | 主语在宾语右侧 | dx 明显为正，dy 接近 0 |
| 2 | 主语在宾语上方 | dy 明显为负，dx 接近 0 |

例如：主语中心 `(0.2, 0.5)`，宾语中心 `(0.8, 0.5)`，输入 `[-0.6, 0.0]`，标签为 0。

示例直接提供这样的人工特征和标签，没有读取真实框。每类 4 条，一共 12 条；每条只分配一个标签。真实图像中同一个物体对可以同时具有多个关系；本课故意构造了互斥标签，才能使用单标签交叉熵。不能把这里的损失直接当成所有场景图模型的配置。

数据张量 `features` 是 `[12, 2]` 的 float32，标签 `labels` 是 `[12]` 的 long。每个标签都是一个类别编号，不是长度为 3 的概率或 one-hot 向量。

## 2. `nn.Module` 和前向计算

模型为：

```text
[N, 2] → Linear(2, 8) → ReLU → Linear(8, 3) → [N, 3]
```

N 是当前 batch 的样本数。`Linear` 对最后一个轴做线性变换，其他轴保留。第一个线性层的权重形状是 `[8, 2]`、偏置 `[8]`；第二个是 `[3, 8]` 和 `[3]`。总参数数为 `8×2+8+3×8+3=51`。

`nn.Module` 管理子层、参数和模型模式。子层在 `__init__` 中创建，计算顺序在 `forward` 中编写。调用 `model(features)` 会执行前向。

```python
class SmallRelationClassifier(nn.Module):
    def __init__(self):
        super().__init__()
        self.input_layer = nn.Linear(2, 8)
        self.output_layer = nn.Linear(8, 3)

    def forward(self, relation_features):
        hidden = torch.relu(self.input_layer(relation_features))
        return self.output_layer(hidden)
```

最后返回 logits，即未归一化的类别得分。模型不要提前做 softmax，再把概率送给本课 `CrossEntropyLoss`。

## 3. 交叉熵的形状与手算

一个 batch 有 4 条数据时：

```text
输入：[4, 2]
logits：[4, 3]，float32
labels：[4]，long，合法编号是 0、1、2
loss：[]，标量
```

对单条数据，logits 为 `[2, 0, 0]`，真实标签为 0。正确类别的 softmax 概率是：

```text
p0 = exp(2) / (exp(2) + exp(0) + exp(0)) ≈ 0.787
loss = -log(p0) ≈ 0.240
```

若三个 logits 都为 0，每类概率是 1/3，损失是 `-log(1/3)=log(3)≈1.099`。这可以用来建立直觉，但随机初始化模型的实际初始损失不一定恰好是 1.099。

`CrossEntropyLoss` 内部完成相应的 log-softmax 和负对数计算。默认对 batch 求平均；本课打印整个训练集的损失也是对 12 条样本求平均。

预测类别通过 `logits.argmax(dim=1)` 得到 `[N]` 的整数编号。用 softmax 后再取 argmax 会得到相同排序，因此单纯计算分类准确率无需 softmax。

## 4. batch、epoch 与更新次数

`TensorDataset` 把特征与标签按样本对应，`DataLoader` 每次取一批。设置 batch_size=4，12 条数据恰好构成 3 个 batch。

- 一个 batch 完成一次前向、求导和更新。
- 一个 epoch 遍历所有 12 条数据。
- 每个 epoch 有 3 次参数更新。
- 若实际跑了 100 个 epoch，则共更新 300 次。

示例会打乱训练顺序，但每轮每条样本仍使用一次。真实数据若最后一个 batch 不满，更新次数通常是 `ceil(样本数/batch_size)`，还要看 `drop_last` 的设置。

## 5. 一次训练迭代

```python
model.train()
optimizer.zero_grad(set_to_none=True)
logits = model(batch_features)
loss = criterion(logits, batch_labels)
loss.backward()
optimizer.step()
```

| 步骤 | 要检查什么 |
| --- | --- |
| `train()` | 模型处于训练模式 |
| 清零 | 当前 batch 梯度不混入上一 batch 的梯度 |
| 前向 | 输入 `[B, 2]`，输出 `[B, 3]` |
| 损失 | 标签类型正确，loss 是有限标量 |
| 反向 | 参数梯度存在且有限 |
| 更新 | 参数根据梯度发生变化 |

示例使用 Adam，学习率 0.03。它的更新规则比第二课普通 SGD 复杂，本课先掌握接口和执行顺序。不要套用 `w-lr×grad` 计算 Adam 的精确更新值。

脚本在首个 batch 打印形状、损失维度和梯度范数，在每个阶段打印训练集损失和准确率。不能只盯着“程序有没有报错”；梯度、参数和损失才说明训练链路是否有效。

## 6. 为什么先过拟合少量数据

小量数据可以帮助排除标签、形状、梯度、优化器等基本问题。这个人工任务很简单，目标是全部 12 条分类正确，并将训练集交叉熵降到较低值。

示例最多训练 300 个 epoch。在至少完成 50 个 epoch 后，如果训练准确率为 100% 且损失小于 0.01，就提前结束。随后检查训练准确率为 100%，损失小于 0.05；不达标会报错，不会把失败训练保存成已通过的教学结果。

具体损失、达到条件的轮数可能随 PyTorch 版本和执行细节变化。示例固定种子并在 CPU 上执行，便于复查，但固定种子本身不构成跨所有环境的完全一致保证。

这个阶段没有独立测试集。这里要回答的是“能否拟合已经见过的人工样本”，所以只报告训练集结果；下一阶段真实实验必须分训练、验证和测试集。

## 7. 评估与关闭梯度

```python
model.eval()
with torch.no_grad():
    logits = model(features)
    predictions = logits.argmax(dim=1)
```

`eval()` 会改变 Dropout、BatchNorm 等层的行为。本课只有 Linear 和 ReLU，所以切换模式不会改变这些层的计算规则，但仍保留标准评估写法，便于后续扩展。

`no_grad()` 关闭评估计算中的梯度记录。`eval()` 本身不关闭自动求导，`no_grad()` 也不负责切换模型模式。下一轮训练前调用 `train()`。

## 8. 保存与加载

本课保存 `state_dict`：参数名称及对应张量的字典。加载时先用同样的类创建模型，再调用 `load_state_dict`。

```python
torch.save(model.state_dict(), checkpoint_path)
loaded_model = SmallRelationClassifier()
state = torch.load(checkpoint_path, map_location="cpu", weights_only=True)
loaded_model.load_state_dict(state)
```

示例只加载刚由自己创建的教学权重。它会比较加载前后的 logits，而不只是比较类别，因为类别相同仍可能存在得分差异。

这个文件用于重现推理，不是完整断点续训文件；续训还需要考虑优化器状态、epoch、配置和随机状态。当前先掌握保存参数与重新加载。

运行方式：在已安装 PyTorch 的环境中切换到本课目录，运行：

```powershell
python .\03_训练循环_示例.py
```

可用 `python .\03_训练循环_示例.py --help` 查看参数。输出目录以脚本所在目录为基准，不受终端当前目录影响。若提示不认识 `weights_only` 参数，先核对 PyTorch 版本和官方文档；本次运行环境未安装 PyTorch，尚未验证具体版本兼容性。

## 9. 常见错误怎么定位

| 现象 | 先检查的地方 |
| --- | --- |
| 输入输出维度不匹配 | Linear 的输入宽度是否为 2；数据是否 `[B, 2]` |
| 标签类型报错 | 标签是否为 long 的 `[B]` 类别编号 |
| 标签越界 | 三类模型的标签是否只在 0～2 |
| `loss.backward()` 失败 | 是否在训练前向用了 `no_grad`，是否提前转成 Python 数字 |
| 梯度一直累加 | 是否每个 batch 都先清零 |
| 参数不变化 | 是否调用 step；优化器是否管理该模型参数 |
| 损失没有明显下降 | 先检查标签和代码路径，再考虑学习率；用少量数据定位 |
| 加载形状不匹配 | 模型层宽或属性名是否与保存时一致 |

每次只改一个条件，并记录改动前后的输入、输出和现象。不要在尚未弄清基本训练链路时堆叠模块。

## 自测与答案

**题 1：** batch_size=4、样本数=12，一个 epoch 更新几次？

答：3 次。每个 batch 一次更新。

**题 2：** `CrossEntropyLoss` 在本例接收什么？

答：`[B, 3]` 浮点 logits 和 `[B]` long 类别编号。模型不用先做 softmax。

**题 3：** `model.eval()` 后还会记录梯度吗？

答：如果未关闭自动求导，仍可能记录；要配合 `no_grad()`。

**题 4：** 这个模型总参数有多少？

答：51。两层权重、偏置分别为 16、8、24、3 个。

**题 5：** 当前到像素输入的 SGDet 还缺什么？

答：至少还需真实图片预处理、视觉特征提取、物体检测及类别预测、候选关系或物体对处理，以及相应监督、后处理和标准评价。具体组成按真实基线核对。

**题 6：** 保存参数后，随意创建不同层宽的模型能直接加载吗？

答：通常不能。参数名称与形状需要匹配；本课使用同样的模型定义。
