本例使用人为编写的两个关系特征：“接触程度”和“归一化距离”。标签约定为 `0=没有拿着`、`1=拿着`。真实场景图需要从图像提取特征，不能仅靠这两个数判断关系。

## 概念表

| 代码名称 | 中文含义 | 本例作用 |
| --- | --- | --- |
| `features` | 输入特征 | 每个样本两个数 |
| `labels` | 类别标签 | 每个样本对应一个类别编号 |
| `nn.Linear(2, 2)` | 线性层 | 两个输入特征，输出两个类别的得分 |
| `scores` | 原始得分 | 还没有转换成概率，可以是负数 |
| `nn.CrossEntropyLoss()` | 交叉熵损失 | 比较原始得分与正确类别 |
| `torch.long` | 长整型 | 本例类别编号使用的数据类型 |
| `argmax(dim=1)` | 每行最大值的位置 | 得到每个样本的预测类别 |
| `TensorDataset` | 张量数据集 | 把每行特征与对应标签配对 |
| `DataLoader` | 数据加载器 | 每次提供一批样本 |

本例把类别编号作为标签；交叉熵接收原始得分和长整型标签，不要先对得分调用 `softmax()` 再传入损失。官方说明见[交叉熵损失](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)。

## 批次、轮次与形状

`batch_size=4` 表示每批四个样本。一共八个训练样本，所以一轮包含两个批次。遍历全部训练样本一次，叫一轮；本例训练三十轮，共更新参数六十次。[数据加载器教程](https://docs.pytorch.org/tutorials/beginner/basics/data_tutorial.html)

| 数据 | 形状 | 含义 |
| --- | --- | --- |
| 全部训练特征 | `[8, 2]` | 八个样本，每个有两个特征 |
| 一批输入特征 | `[4, 2]` | 四个样本，每个有两个特征 |
| 一批输出得分 | `[4, 2]` | 四个样本，每个有两个类别得分 |
| 一批标签 | `[4]` | 四个样本各有一个类别编号 |
| 一批预测类别 | `[4]` | 四个样本各预测一个类别 |

输入、输出刚好都为 `[4, 2]`，含义却不同：输入的第二维是特征，输出的第二维是类别。

## 分类是怎样发生的

假设两个样本的输出是：

```python
scores = torch.tensor([[2.0, -1.0], [-0.5, 1.5]])
predictions = scores.argmax(dim=1)
```

第一行最大得分在位置 `0`，第二行在位置 `1`，预测为 `[0, 1]`。得分 `2.0` 不是“概率为两倍”，这里只比较哪个类别得分更高。

训练仍然是：清除旧梯度 → 计算得分 → 计算损失 → 反向传播 → 更新参数。不要用 `argmax()` 后的类别编号计算交叉熵；取最大位置是作出最终判断的步骤，训练需要原始得分。

## 为什么有验证

训练用八个样本更新参数，验证用另外四个样本检查结果。验证执行 `model.eval()` 和 `torch.no_grad()`，不执行 `backward()` 和 `step()`。`eval()` 切换模型模式；关闭求导由 `no_grad()` 完成。

正确率=预测正确的数量÷样本总数。四个验证样本都预测正确，就是 `100%`。本例数据很容易，四个样本的满分不能说明模型在真实图像上也表现很好。
