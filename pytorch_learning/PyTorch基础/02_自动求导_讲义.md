# 第二课：损失怎样变成参数更新

本课要分清三件事：前向计算得到结果，反向传播得到梯度，优化器利用梯度更新参数。它们分别发生在不同步骤。

配套程序：[02_自动求导_示例.py](02_自动求导_示例.py)。先完成手算，再运行核对。下文给出的数字是预期值；浮点计算可能有很小误差。

## 1. 先用一个标量说明梯度

设：

```text
y = 2x² + 5x
dy/dx = 4x + 5
```

当 `x=3`，`y=2×9+15=33`，梯度为 `4×3+5=17`。这里梯度说明：在当前位置，x 的微小变化会怎样影响 y；它不是 y 的值。

```python
x = torch.tensor(3.0, requires_grad=True)
y = 2 * x ** 2 + 5 * x
y.backward()
print(y.item())       # 33
print(x.grad.item())  # 17
print(x.item())       # 3
```

`requires_grad=True` 让 PyTorch 记录相关运算。`backward()` 沿计算图反向使用链式法则，把关于叶子张量 x 的梯度写入 `x.grad`。求导后 x 仍为 3；参数尚未更新。

`item()` 把只有一个元素的张量变成 Python 数字，适合打印日志。不要在参与损失计算的路径中用它替代张量运算，否则会断开自动求导所需的连接。

## 2. 链式法则不是黑箱

可以把前面的计算拆为：`a=x²`，`b=2a`，`c=5x`，`y=b+c`。

从 `b` 路径传来的导数为 `2×2x=4x`，从 `c` 路径传来的为 `5`；两条路径相加得到 `4x+5`。模型的层更多、参数更多，但梯度计算仍按每个运算的局部导数，从损失向输入和参数方向反向传递。

对一个参数向量，`.grad` 与参数具有相同形状；每个位置对应该参数元素对最终标量损失的导数。通常训练损失是一个标量，才能直接调用无参数的 `loss.backward()`。

## 3. 梯度默认累加

在同一个 x 上重新构造 y 并反向传播，已有 `.grad` 不会自动被覆盖：

```python
y = 2 * x ** 2 + 5 * x
y.backward()
# x.grad 从 17 变为 34
```

这次创建了一个新的计算图，两次反向传播的梯度相加。学习初期如果期待“只保留当前 batch 的梯度”，就需要在每次反向传播前清零。

示例直接操作叶子张量，用 `x.grad.zero_()` 清零后重新求导，又得到 17。训练中使用 `optimizer.zero_grad(set_to_none=True)`，它只处理该优化器管理的参数，通常将已有梯度设为 `None`。

`None` 表示该参数当前没有保存梯度；一个全零梯度张量表示它已有梯度记录，数值恰好为零。两者在代码调试中需要区分。

注意：不要直接对同一个已释放的 y 重复 `backward()`。默认反向传播后，中间计算图信息会释放。本课每次重新做前向计算，不需要 `retain_graph=True`。

## 4. 参数更新手算两次

把参数记作 w，希望它接近目标 1：

```text
L = (w - 1)²
dL/dw = 2(w - 1)
w_new = w_old - learning_rate × gradient
```

选择初始 `w=3`、学习率 0.1，使用无动量、无权重衰减的 SGD。

| 迭代 | 更新前 w | 损失 | 梯度 | 更新后 w |
| --- | --- | --- | --- | --- |
| 1 | 3.0 | 4.0 | 4.0 | `3-0.1×4=2.6` |
| 2 | 2.6 | 2.56 | 3.2 | `2.6-0.1×3.2=2.28` |

对应步骤：

```python
optimizer.zero_grad(set_to_none=True)
loss = (weight - 1.0) ** 2
loss.backward()
optimizer.step()
```

`zero_grad` 清除上一轮梯度；前向计算建立新图；`backward` 计算当前损失的梯度；`step` 根据梯度更新参数。`step()` 本身不会替你完成前向计算或求导，也不会清除梯度。

第二次如果没有清零，梯度会变成 `4+3.2=7.2`，w 会更新为 `2.6-0.1×7.2=1.88`，与上述标准单步 SGD 结果不同。梯度累积也可以被有意使用，但那需要明确设计；本课先掌握每次迭代清零的普通训练。

Adam 等优化器使用的更新规则不同，不应把第三课 Adam 的更新直接手算成普通 SGD。共同点是它们需要当前参数梯度。

## 5. `backward()` 和 `step()` 对照

| 操作 | 主要作用 | 是否更新参数值 |
| --- | --- | --- |
| 前向计算 | 得到输出与损失，建立计算图 | 否 |
| `zero_grad()` | 清理历史梯度 | 否 |
| `backward()` | 计算并累加梯度 | 否 |
| `step()` | 使用梯度和优化器状态更新参数 | 是 |

调试训练时，先检查损失是否为可求导标量，再检查关键参数 `.grad` 是否存在、数值是否有限，最后比较更新前后的参数。只看到损失在打印，不能说明模型正在学习。

## 6. `no_grad()` 用在哪里

评估只需要输出，不需要根据该输出反向更新参数：

```python
with torch.no_grad():
    prediction = weight * 2.0
```

在这个范围内，相关计算不记录反向传播所需的梯度信息。输出的 `requires_grad` 为 False，但原来的 weight 仍是可训练参数。

不要把训练前向和损失放进 `no_grad()` 再期待反向传播成功。第三课的 `model.eval()` 切换模型模式；它不等于关闭梯度。评估一般同时使用 `model.eval()` 和 `torch.no_grad()`。

## 7. 连接到关系模型

关系分类模型输出若干类别得分，标签用于计算损失。梯度会从损失传回分类器、关系特征处理层以及与这些层相连的可训练模块。

未来的多路径融合要检查每条路径收到的梯度：输出形状正确，不意味着该路径真正参与了学习。若中途使用 `detach()`、转成 Python 数字，或在错误位置关闭梯度，可能切断连接。本阶段先能发现这些基本问题，再讨论多路径门控。

## 自测与答案

**题 1：** `backward()` 后参数为什么没变？

答：它计算梯度，参数更新由优化器 `step()` 或显式更新操作执行。

**题 2：** 重建计算图后第二次梯度为 34，是导数公式错了吗？

答：不是。每次梯度为 17，但 `.grad` 默认累加。清零后再计算就得到 17。

**题 3：** `zero_grad()` 放在 `backward()` 与 `step()` 之间为什么有问题？

答：它清掉了刚求出的梯度，优化器没有该次更新需要的梯度。通常在当前迭代反向传播之前清零。

**题 4：** 对 `L=(w-1)²`，w=2，学习率 0.1，一步普通 SGD 后是多少？

答：梯度为 2，更新到 `2-0.1×2=1.8`。

**题 5：** `.grad is None` 是否总意味着代码错？

答：不一定。清零为 None 后还没反向传播是正常的；参数被冻结或未参与当前损失也可能没有梯度。应结合本次计算路径判断。
