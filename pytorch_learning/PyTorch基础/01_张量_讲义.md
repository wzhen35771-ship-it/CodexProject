# 第一课：看懂张量里的数字和维度

本课解决两个问题：模型中的数据如何排布，某个操作改变了哪些维度。静态场景图模型会处理图片、物体特征、物体对特征和关系得分；它们都是张量，但每个轴代表的东西不同。

配套程序：[01_张量_示例.py](01_张量_示例.py)。运行前检查指南中的 PyTorch 环境。先手算，再运行核对。下面的数值是按示例计算的预期结果。

## 1. 张量、形状和数据类型

张量可以理解为带形状的数值数组。`shape` 表示各轴有多少个元素，`dtype` 表示每个元素的数值类型。

```python
import torch

x = torch.tensor([
    [1.0, 2.0, 3.0, 4.0],
    [4.0, 5.0, 6.0, 7.0],
    [7.0, 8.0, 9.0, 10.0],
])
print(x.shape)  # torch.Size([3, 4])
```

这里轴 0 有 3 行，轴 1 有 4 列，总元素数为 `3×4=12`。`[3, 4]` 本身不告诉你这些数是图片、特征还是得分，含义由数据来源决定。

本课浮点数据显式使用 `torch.float32`；第三课的单个类别编号使用 `torch.long`。不要只检查形状而忽略类型。

## 2. 索引从 0 开始

| 写法 | 含义 | 结果 | 形状 |
| --- | --- | --- | --- |
| `x[1]` | 第二行 | `[4, 5, 6, 7]` | `[4]` |
| `x[:, -1]` | 所有行的最后一列 | `[4, 7, 10]` | `[3]` |
| `x[0, 1]` | 第一行第二列 | `2` | `[]`，标量 |
| `x[1:2]` | 保留第二行的切片 | `[[4, 5, 6, 7]]` | `[1, 4]` |

`:` 表示该轴的全部元素，负数索引从末尾数。整数索引通常移除对应轴；切片保留该轴。这对维度调试很重要：`x[1]` 与 `x[1:2]` 含有相同的四个数，但形状不同。

## 3. `sum(dim=...)` 是沿指定轴汇总

`x.sum(dim=0)` 把三行合起来，每列保留一个值：

```text
第一列：1 + 4 + 7 = 12
第二列：2 + 5 + 8 = 15
第三列：3 + 6 + 9 = 18
第四列：4 + 7 + 10 = 21
结果：[12, 15, 18, 21]，形状 [4]
```

`x.sum(dim=1)` 把每行的四列合起来：

```text
第一行：1 + 2 + 3 + 4 = 10
第二行：4 + 5 + 6 + 7 = 22
第三行：7 + 8 + 9 + 10 = 34
结果：[10, 22, 34]，形状 [3]
```

默认会移除被汇总的轴。`x.sum(dim=1, keepdim=True)` 得到 `[[10], [22], [34]]`，形状 `[3, 1]`，方便后续广播。不能把 `dim=0` 固定背成“横向”或“纵向”；对三维以上张量，应根据每个轴的含义判断。

## 4. 广播：较小张量如何参与逐元素计算

广播从最右侧维度开始对齐。两侧对应尺寸相等，或者其中一个为 1，就可以配对；缺少的左侧维度按 1 处理。

例如：

```python
offset = torch.tensor([1.0, 2.0, 3.0, 4.0])
centered = x - offset
```

形状对齐：`[3, 4]` 与 `[4]`，相当于 `[3, 4]` 与 `[1, 4]`。每行都减去同一组四个数，得到：

```text
[[0, 0, 0, 0],
 [3, 3, 3, 3],
 [6, 6, 6, 6]]
```

一个 `[3]` 向量不能直接按每行减到 `[3, 4]` 上：最右侧的 3 与 4 不兼容。要按行减，先把它变成 `[3, 1]`。

实际应用：图片三个通道各用一个均值和标准差。对 `[C, H, W]`，通道均值应是 `[C, 1, 1]`；对 `[N, C, H, W]`，可明确写成 `[1, C, 1, 1]`。这让每个通道的所有像素使用同一个参数。

## 5. `reshape` 和 `permute` 各做什么

`reshape` 改变形状，不改变元素总数。它适合把已有元素组织成新形状，例如 `[3, 4] → [2, 6]`。`-1` 表示让 PyTorch 推算该轴大小；`x.reshape(2, -1)` 得到 `[2, 6]`。不能把 12 个元素变为 `[5, 3]`。

`permute` 交换轴的顺序。例如图片轴从 `(H, W, C)` 改成 `(C, H, W)`，应该用：

```python
image_chw = image_hwc.permute(2, 0, 1)
```

参数 `2, 0, 1` 的意思是：新轴 0 来自旧轴 2，新轴 1 来自旧轴 0，新轴 2 来自旧轴 1。轴交换保持某个像素与它的 RGB 通道对应关系。

仅用 `image_hwc.reshape(C, H, W)`，虽然目标形状相同，但会按原有逻辑元素顺序重新分组，把像素与通道的对应关系弄错。`reshape` 不能代替轴交换。

补充：`permute` 通常返回共享底层数据、步幅改变的视图。当前阶段知道“形状与排列方式都要核对”即可。若后续遇到 `view` 的连续内存报错，查官方文档；这里用 `reshape`，不展开内存布局优化。

## 6. 一张人工 RGB 图片

本课图片高 2、宽 3，每个像素有 R/G/B 三个值：

```text
第 0 行：[10,20,30]   [40,50,60]   [70,80,90]
第 1 行：[100,110,120] [130,140,150] [160,170,180]
```

每个三元数组是一个像素的 RGB。原始张量 `[2, 3, 3]` 采用 HWC 排列，第二行第三列像素为 `image_hwc[1, 2, :]`，结果 `[160, 170, 180]`。

变为 CHW 后，形状是 `[3, 2, 3]`，同一像素通过 `image_chw[:, 1, 2]` 取出，仍为 `[160, 170, 180]`。R 通道整个平面是：

```text
[[10, 40, 70],
 [100, 130, 160]]
```

`unsqueeze(0)` 添加批次轴，得到 `[1, 3, 2, 3]`。`torch.stack([image_chw, image_chw], dim=0)` 得到两张图片组成的 `[2, 3, 2, 3]`。批次大小表示本次同时处理几张图片，不是图片尺寸。

| 步骤 | 形状 | 轴含义 |
| --- | --- | --- |
| HWC | `[2, 3, 3]` | 高、宽、通道 |
| CHW | `[3, 2, 3]` | 通道、高、宽 |
| 单图 batch | `[1, 3, 2, 3]` | 图片数、通道、高、宽 |
| 双图 batch | `[2, 3, 2, 3]` | 图片数、通道、高、宽 |

示例先除以 255，把人工的 0～255 数值放到 0～1 范围，再计算 `(image - mean) / std`。教学用 `mean=std=0.5`，不是任何真实模型的预处理配置。比如值 10 归一化后是 `(10/255-0.5)/0.5≈-0.9216`。真实基线必须使用该基线要求的预处理。

## 7. 连接到静态场景图

图片可能是 `[N, C, H, W]`，物体特征可能是 `[N, Q, D]`，关系得分可能是 `[N, Q, Q, P]`。这里 N 是 batch 大小，Q 是候选物体或查询数，D 是特征维度，P 是关系类别数。只是常见接口示意，具体形状以实际基线为准。

`[N, Q, Q, P]` 中两个 Q 的顺序通常分别表示主语与宾语；不能因尺寸相同就随意交换。学习时总是记录“该轴是什么”，不要只记录数字。

## 自测与答案

**题 1：** `x[1]` 和 `x[1:2]` 为什么形状不同？

答：整数索引取出一行并移除行轴，得到 `[4]`；切片保留行轴，得到 `[1, 4]`。

**题 2：** `[2, 3, 4]` 对 `dim=1` 求和后是什么形状？保留维度呢？

答：分别是 `[2, 4]`、`[2, 1, 4]`。

**题 3：** `[4, 3, 2, 5]` 的 batch 图片，通道均值最清楚写成什么形状？

答：`[1, 3, 1, 1]`。3 个值分别对应三个通道，其他轴广播。

**题 4：** HWC → CHW 为什么不直接 `reshape`？

答：需要交换轴并保留像素通道对应；仅改形状会按原元素顺序重新分组。

**题 5：** `*` 与 `@` 相同吗？

答：`*` 做逐元素乘法并可广播；二维 `@` 做矩阵乘法，内侧维度要一致。例如 `[2, 3] @ [3, 4] → [2, 4]`。
